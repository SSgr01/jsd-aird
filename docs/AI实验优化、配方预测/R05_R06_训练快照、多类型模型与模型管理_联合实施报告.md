## 2. 已完成的实现

### 2.1 Snapshot、任务和制品

- 新增 `V59__ai_rnd_training_and_model_registry.sql`，补充组织级自动学习设置、每 Y 训练意图、快照配置版本、任务/attempt、制品、模型版本和发布字段。
- Snapshot 冻结 Y 定义、输入方案、来源映射、材料字典、预处理、策略版本、授权范围、资格运行、事实高水位、稳定排序后的样本值和随机种子；时间和运行 ID 不参与业务指纹。
- 98.8% 的实际配方比例在 Snapshot 和 Parquet 中保持原值，不补齐、不归一化。
- 同一业务指纹复用逻辑任务；重试复用原 Snapshot，仅增加 attempt。任务和 Worker 具备幂等键、租约令牌、generation fencing、取消、重试和过期结果隔离。
- 对象存储、Snapshot、Snapshot 条目、终态 attempt、制品和已发布模型内容受数据库不可变保护。训练制品使用内容寻址哈希登记。
- Worker 运行时只注册新的 `TrainingJobHandler`，旧 V1 模型构建 Controller、Service、Facade、SnapshotBuilder 及运行时写入链路已移除；旧物理表按 R10 清理计划暂时保留。

### 2.2 多类型训练与发布门禁

已启用内部 `formula-model.v2` 快照校验、验证折和训练路由：

- 连续值使用 Gaussian Process 候选；
- 序数使用 Ordinal Cumulative Logit；
- 二分类和多分类使用类型化分类模型候选；
- 文本、下界观测和不支持类型不会伪装成普通连续或分类标签；
- `FORMULA_LINEAGE` 与 `SOURCE_CONTEXT` 分组共同用于验证，Candidate 与同折基线使用同一验证样本；
- 无同口径正式模型时比较状态为 `NOT_COMPARABLE`，不能自动替换 ACTIVE；
- `SYNTHETIC` 模型永久 `productionEligible=false`，启用接口返回结构化 `MODEL_NOT_PRODUCTION_ELIGIBLE`；
- 每组织每 Y 的 ACTIVE 唯一约束、并发版本校验、暂停和回退接口已落实。

Python `InputFieldV2` 与 Java 镜像类型已同步冻结字段，V1 载荷仍会被 V2 严格 Schema 拒绝。

### 2.3 模型管理页面

新增 `/assistant/model-management`：

- 顶部自动学习总开关、最近检查和“立即检查”；
- 模型目录、训练任务两个页签；
- 按性能分类、模型状态和关键词筛选；
- 业务名称、结果类型、训练数据量、版本和验证表现使用中文展示；
- 训练任务详情显示进度和运行记录；
- 模型详情默认隐藏 UUID、哈希和冻结 JSON，放在“高级信息”；
- Candidate 仅显示待评估，合成模型展示不能生产启用，启用按钮按权限和门禁禁用；
- 活跃任务每 3 秒刷新，刷新页面后按后端状态恢复；
- 模型管理、训练操作和发布动作分别使用 `ai.model.read`、`ai.training.operate`、`ai.model.publish` 权限。
