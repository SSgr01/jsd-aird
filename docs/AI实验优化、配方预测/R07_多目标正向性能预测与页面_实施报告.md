## 1. 本轮范围

本轮完成多目标正向性能预测闭环。页面为 `/assistant/performance-prediction`，一次请求可以选择多个 Y；后端在请求创建时固定 ACTIVE 模型、Y/X、Snapshot、DOMAIN 和 QUALITY 版本，逐 Y 执行门禁并返回类型化结果。本轮不实现配方反向搜索、实验优化或实验草稿创建。

R07 复用 `ai.modeling_policy_version(kind=QUALITY)`，没有新增第二套 QUALITY 生命周期。98.8% 或 100% 的配方总量均保留实际输入值；是否影响可信度由冻结的 QUALITY 策略决定，代码没有写死比例阈值。

## 2. 实现与修正

- V60 `ai_rnd_performance_prediction` 增加 QUALITY 策略按 Y 绑定、预测记录不可变内容、请求级 `execution_status` 与业务级 `outcome_status`、逐 Y 结果和终态 HTTP 状态。
- Java `PredictionService` 按目标类型传递二分类正类，避免二分类模型因 `positiveClass` 缺失被 Python 契约拒绝。
- Python V2 对请求校验错误输出可序列化的结构化 422，不再因 Pydantic 错误上下文导致 500。
- 相同组织、操作者、预测类型和幂等键的并发请求只由一个请求取得执行权；后续请求在首条仍为 `RUNNING` 时返回 202，终态后重放首条响应。相同键不同请求体返回 409。
- 页面按连续、序数、二分类、多分类分别渲染结果；阻断目标不包含预测值、等级或概率。结果卡不再重复显示“配方按实际合计参与预测，系统未补齐或归一化”提示，实际比例警告仍保留在输入区和质量证据中。
- 页面收到 202 后按记录 ID 查询，刷新或重新进入仍由服务端恢复状态；普通界面隐藏 UUID、哈希和内部任务术语，证据抽屉才展示冻结版本。

## 4. API 场景验收

使用隔离库中的合成 ACTIVE 模型完成以下场景。合成模型均为 `data_nature=SYNTHETIC`、`production_eligible=false`。

| 场景 | 结果证据 |
|---|---|
| 四目标全部成功 | HTTP 200，`executionStatus=SUCCEEDED`、`outcomeStatus=SUCCEEDED`；连续、二分类、多分类、有序等级四类结果均有类型化值 |
| 部分成功 | HTTP 200、`outcomeStatus=PARTIAL`；60°光泽成功，PC 170μm UV 后卷曲角因 `OUT_OF_DOMAIN` 阻断且不含预测值 |
| 全部业务阻断 | HTTP 200、`outcomeStatus=BLOCKED`；多个 Y 均为 `MISSING_REQUIRED_X`，请求执行本身成功 |
| 单 Y 阻断 | HTTP 422；请求为 `SUCCEEDED/BLOCKED`，逐 Y 只有结构化原因 |
| 计算服务失败 | Python 进程停止后 HTTP 503；请求为 `executionStatus=FAILED`、`outcomeStatus=null`，各目标为 `COMPUTE_UNAVAILABLE`，没有伪造预测 |
| 同键并发 | 冷启动期间两个相同请求只有一次调用计算服务；首条 HTTP 200，另一条 HTTP 202，返回同一个 `predictionRecordId` 和 `RUNNING` |
| 终态重放 | 同键同请求再次返回首条保存的 HTTP 200 和 `predictionId`，没有重新评分 |
| 请求体冲突 | 同键不同请求体在运行中和终态后均返回 HTTP 409 `IDEMPOTENCY_CONFLICT` |
| 刷新恢复 | 浏览器刷新后仍显示已保存的终态结果；202 记录通过 `GET /prediction-records/{id}` 恢复 |

数据库当前预测记录按状态核对为：`SUCCEEDED/SUCCEEDED` 14 条、`SUCCEEDED/PARTIAL` 3 条、`SUCCEEDED/BLOCKED` 16 条、`FAILED/null` 21 条。失败记录不会被表示为 PARTIAL。

## 5. 浏览器全链路验收

真实页面 `http://127.0.0.1:5175/assistant/performance-prediction` 使用隔离账号和合成数据逐项验证：

1. 选择 60°光泽、UV 表干、外观等级、铅笔硬度四个 Y，页面显示逐 Y“正式模型、输入方案和策略已固定”。
2. 输入树脂 80%、助剂 18.8%、测试温度 25°C 后，页面显示“全部完成”；结果分别为连续值 50.87 GU、二分类“未表干”及概率、多分类“透明”及概率分布、有序等级 H 及概率。
3. 选择 60°光泽和 PC 170μm UV 后卷曲角，页面显示“部分完成”；第二个目标仅显示“输入超出模型适用域”。
4. 清空必需测试温度后，所有选中目标均显示“缺少模型要求的输入字段 / MISSING_REQUIRED_X”，没有结果卡数值。
5. 停止 Python 计算服务后提交，页面显示“本次预测未能正常执行”，逐目标显示“模型异常 / COMPUTE_UNAVAILABLE”；重启服务后使用新幂等键可再次完成预测。
6. 打开“查看预测依据”，能看到模型版本、Y 定义、输入方案、Snapshot、DOMAIN 和 QUALITY 版本；页面提示结果固定使用提交时版本。
7. 页面刷新后结果仍在，浏览器控制台没有新增错误或警告；结果卡不再出现已删除的实际合计归一化说明。

模型管理页 `/assistant/model-management` 同时显示 19 个隔离验收模型为“使用中”，性能预测页因此可以进行真实评分。调用生产启用接口仍返回 HTTP 422 `MODEL_NOT_PRODUCTION_ELIGIBLE`，这是 R06/R07 的正确门禁，不能把合成模型标记为生产启用；R11 使用真实样本、SOP、阈值和适用域完成后才允许生产资格。
