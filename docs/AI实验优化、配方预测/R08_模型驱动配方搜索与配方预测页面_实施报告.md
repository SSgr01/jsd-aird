## 1. 交付范围

本轮完成 `/assistant/formula-prediction` 的模型驱动配方预测闭环。页面以结构化表单承载目标与约束、材料与配方空间、实验前条件、条件确认和候选对比；自然语言输入只用于辅助填写。一次运行可以绑定多个 Y 及各自的 ACTIVE 模型、输入方案、材料字典、DOMAIN 和 QUALITY 版本。

R08 只负责搜索、评分和比较候选，不创建实验草稿。候选转实验草稿留给 R09。隔离验收使用合成 ACTIVE 模型，均保留 `production_eligible=false`，没有把测试模型伪装成生产模型。

## 2. 数据库与运行状态

- 新增 `V61__ai_rnd_formula_design.sql`，未改写 V57～V60。隔离数据库日志确认 V1～V61 共 61 个迁移已校验并执行，当前版本为 61。
- `ai.research_run_v2` 保存请求号、契约版本、冻结模型绑定、搜索配置、随机种子、进度和执行心跳；请求哈希、目标、配方、模型和搜索空间在创建后不可修改。
- 运行状态拆分为 `execution_status=QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED` 与 `outcome_status=SUCCEEDED/PARTIAL/BLOCKED`。系统故障、模型制品损坏和加载失败属于 `FAILED`；约束无解或适用域阻断属于正常完成后的 `BLOCKED`。
- `ai.research_candidate_v2` 保存每个请求目标的类型化结果、QUALITY、DOMAIN、硬规则、评分、搜索策略和完整证据，并以规范化请求内容生成唯一内容哈希。候选生成后不可修改或删除。
- 运行和候选使用组织、操作者、运行类型和 `Idempotency-Key` 约束；同键不同请求体返回 `409 IDEMPOTENCY_CONFLICT`，同键相同请求只生成一个 run 和一个异步任务。R08 没有新增 `quality_policy_version`，QUALITY 继续复用 `ai.modeling_policy_version(kind=QUALITY)`。

## 3. 后端与 Python V2

Java 新增 `FormulaDesignController`、`FormulaDesignService`、`FormulaDesignRepository` 和 `FormulaDesignJobHandler`，落实以下接口：

- `GET /api/v1/ai/rnd/formula-design-context`
- `POST /api/v1/ai/rnd/research-requests/parse`
- `POST /api/v1/ai/rnd/formula-designs`
- `GET /api/v1/ai/rnd/research-runs`
- `GET /api/v1/ai/rnd/research-runs/{id}`

创建运行前服务端校验目标绑定、固定模型、材料字典交集、必需 X、固定比例、变量空间、目标总量和目标数量。比例按请求原值处理：100% 和 98.8% 都能作为明确的 `targetTotal`，不补余量、不归一化；比例之和、固定比例超限和上下界无解直接返回结构化 422。

Python `formula-model.v2` 新增 `POST /internal/v2/models/recommend`。请求使用类型化目标、材料变量、输入变量和约束，批量加载冻结模型并返回候选和逐 Y 评分。Java 在返回边界再次检查总量、材料和输入规则，损坏 bundle、SHA 不一致、契约不匹配或加载失败不会生成候选。

搜索过程固定请求中的模型版本和随机种子；ACTIVE 在运行期间切换不会改变本次运行。搜索结果不足请求数量时返回真实数量和 `PARTIAL`，没有可行候选时返回 `BLOCKED`，不会调用旧案例或伪造方案补数。

## 4. 页面交付

页面位于 `/assistant/formula-prediction`，已按 V3.7 信息顺序实现：

1. 选择多个目标并按结果类型展示连续值、序数、二分类或多分类目标的运算和门槛。
2. 展示固定/可变材料、材料比例、目标合计和当前配方合计；材料使用业务编码，不在普通界面显示 UUID。
3. 展示实验前固定条件和可选的一句话需求入口。
4. 提交前显示目标、总量、材料合计和模型绑定的条件确认。
5. 运行中显示检查条件、搜索方案、模型评估、规则终审和整理候选进度。
6. 结果按候选卡展示配方、实际总量、逐 Y 结果、评分和终审说明，并明确请求数量与实际数量。
7. 页面收到 202 时按 runId 轮询；刷新或重新进入页面时从服务端恢复运行和候选。修改目标、运算、目标值或材料比例会清除旧运行结果。
8. 普通界面隐藏哈希、Worker 和内部 JSON；冻结模型、Snapshot、DOMAIN、QUALITY 等证据仅在高级信息中查看。

页面没有“创建实验草稿”按钮，也没有提前实现 R09 的实验关联。

## 6. 真实浏览器验收

真实服务为 Web `5175`、Java API `18080`、Python V2 `18090`，浏览器逐项验证：

1. 进入配方预测页面，选择“60°光泽（合成验收）”和“UV表干（合成验收）”，页面展示两个目标卡、材料输入和测试温度。
2. 提交 50% RESIN + 50% ADDITIVE、25°C，页面显示搜索进度完成和 4/4 候选；候选卡显示中文目标名称、配方比例和二分类结果。
3. 将材料比例从 50/50 改为 51/50 后，页面立即清除旧候选并显示新的 101% 条件；修回 50/50 后重新提交成功，确认旧结果不会被继续使用。
4. 将光泽目标改为不可达的高值，页面正常完成搜索但显示“没有可行候选”，没有凑数方案。
5. 停止 Python 计算服务后提交，页面显示“执行失败”和错误提示；重启服务后使用新幂等键可恢复正常搜索。
6. 刷新成功运行页面，目标选择、模型固定信息、运行进度和候选结果均从服务端恢复；浏览器控制台没有新增错误或警告。
