## 3. Worker 并发、租约与迟到结果

`PostgresWorkRepository.claimJob` 对 `AI_FORMULA_DESIGN_V2` 与 `AI_EXPERIMENT_OPTIMIZATION_V2` 使用组织级事务 advisory lock，并检查同组织未过期的 RUNNING AI 任务。相同组织的第二个不同运行不会越过“组织并发 1”；租约重新认领会递增 `lease_generation` 并生成新令牌，心跳、完成和失败更新必须同时匹配令牌与代次。

验收脚本 [r09_worker_concurrency_fencing.java](../../scripts/testdata/r09_worker_concurrency_fencing.java) 使用同一组织、不同运行类型的两个 READY 任务，保持第一个 claim 事务打开后执行第二次 claim，再使第一条 lease 过期并重新认领。结果文件 [worker-concurrency-fencing.json](../../tmp/r09-worker-evidence/worker-concurrency-fencing.json) 为：

```json
{"differentRunTypes":"AI_FORMULA_DESIGN_V2+AI_EXPERIMENT_OPTIMIZATION_V2","sameOrgSecondClaim":"EMPTY","firstGeneration":1,"reclaimedGeneration":2,"staleCompletionRows":0,"currentCompletionRows":1}
```

这同时证明了不同运行类型的组织并发闸门、过期租约重新认领、旧 Worker 迟到完成被拒绝和新代次完成成功。Worker 退出、重试、重复投递与当前版本恢复沿用 R08 的 generation fencing 和 `ops.async_job` 租约机制。
