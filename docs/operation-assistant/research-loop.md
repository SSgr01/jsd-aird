# 助手实验优化与原料资料

入口为研发助手和实验优化。原料资料通过助手读取。日报、周报、复盘全文保留在当前对话，项目文档保存暂不提供。

## 原料档案

配方仍使用原有内部编号。助手可读取编号关联的牌号、生产商、供应商、材料类别和配方作用。物性和已知组成分别记录数值、单位、适用条件及含量范围；官能团、名义官能度与机理单独记录。后端保留原料档案、来源版本和读写接口。

每条事实引用一份不可改写的来源版本，并标记原文行号和摘录。档案修订产生新版本，旧轮次继续引用原版本。未披露部分保持未知，推断机理和研发参考资料均明确注明性质。来源打开时重新核对当前权限。

## 对话中的建模与推荐

1. 明确项目、目标指标和条件，读取配方编号对应的原料资料及文献原文。
2. 选择已完成、方法和条件可比的实验样品，明确 X 与 Y。计算上下文按页读取，继续读取 `next_offset`，不要只采用第一页。
3. 发起训练后说明参与样品数、效果指标和适用范围。训练结果须收到明确启用指令后才注册并启用。
4. 按当前模型版本预测。提出实验建议时说明具体变量、条件、指标、出处、适用范围、本项目差异和待实测事项。
5. 选择候选并生成实验草稿。服务端填写各样品列的配方和工艺，保留原料编号，实测区域留空。名称、日期和方案由用户明确给出。

沿用已完成建模的样品与 X/Y 时，使用 `get_compute_context(kind=EXPERIMENT_OPTIMIZATION, training_run_id=...)` 返回的 `request_draft`，补充方向与边界后提交。平台重新核对来源权限和版本；来源已变化时重新选择。引用已读取的文献或原料资料时，`source_refs` 及 `research_basis.source_ref` 可使用 `{ "evidence_id": "实际证据身份" }`，由平台恢复固定出处，不手工拼接来源身份。

研究依据与项目关系由服务端保存，切换设备或继续对话后仍可读取。不要仅在浏览器中记录候选与实验的关系。

## 实测记录与下一轮

通过 `get_experiment_loop` 取得关联实验、当前版本、修订号、样品身份及指标字段，再保存用户提供的读数。可附实际测定方法和条件；这些信息属于该样品版本，不改标准模板。单位换算沿用实验原字段，空白、未测与零值分别保留。

助手只保存可编辑草稿。提交、审核和完成在原实验页面办理。实际执行的配方或工艺变化，应在实验中如实填写。未完成记录和候选页面上的暂存读数不能直接进入下一轮。

正式完成后，闭环按当前有效版本提取实际 X/Y，展示推荐与实际配方差异、预测偏差和结果覆盖情况。方法、单位或固定条件不相容的结果保留原因；方法缺失不视为相同。有审核权限的人员可在已发布实验中选择「作废实验」并填写原因。失效读数退出后续学习，历史轮次仍保留原快照。

每轮固定数据、模型、边界、原料资料和文献依据。下一轮按实验与样品身份去重，纳入新增有效结果。调用结果未知时先查原操作回执，避免重复训练、生成草稿或保存读数。

## 日报、周报与复盘

日报说明当日进展、待办、阻塞和建议；周报说明本周变化、模型与实验成果、优化进展和下周安排。复盘列出实验版本、推荐与实际执行差异、预测与实测偏差和下一轮建议。项目活动中的运行身份可继续读取完整计算结果。

沿用原生定时任务，保留用户设置的时间、启停状态与删除记录。周期按 `Asia/Shanghai` 计算，后台报告只读取现有业务结果。报告数字应能追溯到实际运行、实验版本和样品，遇到缺项明确说明。
