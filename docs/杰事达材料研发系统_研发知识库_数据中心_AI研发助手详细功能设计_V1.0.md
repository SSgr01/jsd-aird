### 0.2 已确认产品决策

1. 数据中心定位为**统一汇聚的结构化研发数据资产中心**。
2. AI研发助手中的“文件检索”**只搜索文件，不搜索结构化数据记录**。
3. 研发知识库资料审核统一由**资料管理员**负责。
4. 生成式大模型确定**只使用外部大模型**。
5. AI问答允许**实时搜索互联网**。
6. 一期暂不建设复杂的用户/部门/项目级权限体系。
7. 即使一期不做复杂权限，**AI外发安全门禁必须保留**。
8. 研发知识库采用“**知识审核与AI使用授权分离**”的设计。
9. AI问答允许查询数据中心的**正式结构化数据**。
10. 数据中心中：基础主数据允许新增/编辑；已有完整业务流程的数据只做统一汇聚和查询，不在数据中心直接修改。
11. AI回答允许保存，并进一步保存为**不可变AI回答快照**。
12. 文件、数据、模型后续变化时，历史项目必须能够追溯“当时AI使用的原文件版本、数据版本与外部参考”。

# 第一篇 《研发知识库详细功能设计》

**项目：** 杰事达材料研发系统  
**模块：** 研发知识库  
**版本：** V1.0-Draft  
**设计状态：** 可进入原型细化 / 前后端评审  
**本次范围：** 研发知识库 →「资料上传」「知识库查看」，以及由这两个页面进入的审核、详情、版本、知识页等二级业务页面。

## 1. 模块定位

研发知识库定位为：

> **杰事达研发文件及经过人工确认的知识资产管理中心。**

核心不是“把文件放进去”，而是将 PDF、Word、Excel、PPT、图片、音频等研发资料经过解析、分类、标准化、人工确认、版本管理后，形成可查询、可追溯、可用于AI的可信知识资产。

| 模块 | 核心资产 | 主要用途 |
|---|---|---|
| 研发知识库 | 文件、解析内容、知识条目、知识页、文件版本、知识来源 | 找资料、读资料、形成知识、供AI使用 |
| 数据中心 | 结构化业务数据 | 数据查询、统计、关联、AI结构化分析 |
| AI研发助手·文件检索 | 知识库及数据中心来源文件 | 找文件，不搜索结构化记录 |
| AI研发助手·AI问答 | 已授权知识 + 已确认结构化数据 + 实时互联网 | 生成带依据的研发回答 |

## 2. 功能范围

左侧导航保持：

**研发知识库**
- 资料上传
- 知识库查看

审核、详情、版本管理、知识页作为内部页面由业务操作进入。

## 3. 核心业务对象设计

| 对象 | 产品含义 | 关键关系 |
|---|---|---|
| KnowledgeDocument | 一份逻辑文档 | UA-1117 TDS |
| DocumentVersion | 文档的某个不可变版本 | V1.0、V2.0 |
| FileObject | 原始上传文件 | PDF/XLSX/DOCX等 |
| ParseJob | 文件解析任务 | 一个版本可多次解析 |
| ExtractionDraft | 自动抽取结果 | 人工审核前草稿 |
| KnowledgeRelation | 文档与项目/产品/实验等关系 | UA-1117、PRJ-003 |
| KnowledgePage | 按业务对象聚合形成的知识页面 | UA-1117产品知识页 |
| SourceAnchor | 原文定位锚点 | PDF第3页、Sheet1!B12 |
| AiUsageGrant | AI使用授权记录 | 当前版本是否允许外部AI使用 |
| CitationReference | 其他对象对该版本的历史引用 | AI回答、项目资料等 |
| AuditRecord | 操作日志 | 谁在何时审核/授权/更新 |

核心规则：

> **逻辑文档可以变化，但历史 DocumentVersion 永远不能被覆盖。**

## 4. 状态模型设计

### 4.1 文件处理状态 `parseStatus`

| 状态 | 含义 |
|---|---|
| 待上传 | 已加入上传队列 |
| 上传中 | 原始文件正在上传 |
| 待解析 | 原文件上传成功 |
| 解析中 | OCR/文档解析/抽取处理中 |
| 解析成功 | 已生成解析结果 |
| 解析失败 | 文件解析失败 |

### 4.2 知识生命周期 `knowledgeStatus`

| 状态 | 含义 |
|---|---|
| 待审核 | 解析结果等待资料管理员确认 |
| 已发布 | 已成为正式知识 |
| 审核驳回 | 当前版本审核未通过 |
| 已停用 | 不再作为当前有效知识 |

### 4.3 AI授权状态 `aiUsageStatus`

| 状态 | 含义 |
|---|---|
| 未授权 | 不允许发送外部AI |
| 已授权 | 允许作为AI问答知识来源 |
| 已撤销 | 曾允许，后续已禁止 |

默认状态：

> **未授权**

并且：

> **知识发布 ≠ AI授权。**

## 7. 文件格式

| 类型 | P0处理方式 |
|---|---|
| PDF | 文本解析；扫描PDF启动OCR |
| Word | 段落、标题、表格解析 |
| Excel | Sheet、单元格、表头、表格解析 |
| PPT | 页面及文本解析 |
| JPG/PNG等 | OCR + 原图 |
| 扫描件 | OCR |
| MP3/WAV等音频 | ASR转写 + 时间戳 |
| ZIP | 解压后逐文件形成上传任务 |

视频暂不列入P0正式验收格式。

## 8. 待上传区

展示：文件名、格式、大小、当前分类、状态、移除。

操作：
- 清空
- 开始上传

每个文件独立显示进度，单文件失败不影响其他文件。

## 9. 重复文件判断

### 9.1 完全重复

根据SHA-256判断。

提示：
> 当前文件与已有文件内容完全一致，无需重复上传。

操作：
- 查看已有文件
- 取消上传

### 9.2 疑似新版本

文件名接近、关联对象相同、Hash不同。

操作：
- 作为新版本
- 作为新文档

禁止静默覆盖旧文件。

## 10. 上传后的处理流程

> 上传原文件 → 文件完整性检查 → 自动识别类型 → 内容解析 → 字段抽取 → 标准化 → 异常检查 → 生成待审核草稿 → 资料管理员审核 → 发布知识 → 单独设置AI使用授权

## 19. AI使用授权

只有已发布知识才能授权。

提示：
> 开启后，AI研发助手可以将与问题相关的必要知识片段发送至配置的外部大模型。原始文件不会整体发送给模型。

操作：
- 取消
- 确认授权

## 20. 撤销AI授权

撤销后：
- 后续AI不再使用
- 历史AI回答快照、引用和证据链保留

## 21. 新版本AI授权规则

AI授权绑定DocumentVersion。

新版本发布后默认未授权，不继承旧版本授权。

## 27. SourceAnchor

PDF：fileVersionId + page + paragraph/bbox  
Excel：fileVersionId + sheet + cell/range  
Word：fileVersionId + heading + paragraph  
音频：fileVersionId + startTime + endTime

## 28. 版本管理

新版本上传填写：
- 新文件
- 版本说明
- 变更说明

新版本未审核前旧版本仍为当前正式版本。

新版本发布后：
- V2 → 当前版本
- V1 → 历史版本

历史引用仍指向V1。

## 29. 引用影响

若旧版本已被引用，显示影响数量。

操作：
- 查看旧版本
- 查看最新版本
- 基于最新资料重新生成（由AI问答提供）

## 30. 停用资料

不能直接物理删除已发布资料。

停用后：
- 默认知识库搜索不返回
- 默认文件检索不返回
- AI不再使用
- 历史引用仍可访问

## 31. 知识页

文件详情看一份文件；知识页看一个研发对象的综合知识。

知识页类型：
- 产品
- 批次
- 配方
- 工艺
- 实验
- 检测
- 图谱
- 标准
- 复盘
- 文献
- 质量案例

知识页长期维护、可追溯，不是AI临时摘要。

## 32. 与文件检索联动

已发布且当前有效知识可被文件检索。

AI授权不影响普通文件搜索。

## 33. 与AI问答联动

AI问答只使用：
> 已发布 + AI已授权 + 当前有效版本

## 34. 重新解析

适用于解析失败或解析规则升级。

已发布资料重新解析后必须再次人工确认，不能自动替换正式结果。

## 35. 操作审计

记录：上传、解析、字段修改、审核、驳回、AI授权/撤销、新版本、停用、重新解析、分类调整等。

## 9. 数据上传流程

> 选择数据类型 → 选择数据模板 → 上传文件 → 解析文件结构 → 确认Sheet/表头 → 字段映射 → 数据标准化 → 异常检查 → 数据预览 → 确认导入 → 生成导入结果/对账报告

## 10. Step 1：选择数据类型

| 字段 | 必填 | 说明 |
|---|---:|---|
| 数据类型 | 是 | 物料 / 配方 / 工艺 / 设备 / 标准 / 历史生产检测等 |
| 导入方式 | 是 | 新增数据 / 更新已有数据 |
| 数据模板 | 是 | 已发布数据库导入模板 |
| 关联项目 | 否 | 项目型历史数据 |
| 文件 | 是 | 一个或多个文件 |

## 15. 字段映射方式

### 映射已有字段
选择已有 `field_code`。

### 申请新增字段

### 忽略字段
不进入结构化数据，但原文件完整保留。

## 16. 新字段原则

禁止直接给数据库随意增加字段。

必须：

> 新字段候选 → 设置类型、单位、语义 → 确认 → 生成稳定field_code → 加入映射

## 17. 数据标准化

保存：
- raw_value
- raw_unit
- normalized_value
- normalized_unit

例如：

| 原始值 | 标准值 |
|---|---|
| UA1117 | UA-1117 |
| UA 1117 | UA-1117 |
| CPS | cps |
| 0.43 Pa·s | 430 cps |

单位维度不兼容时阻断导入。

## 18. 主数据匹配

系统匹配：
- 标准编号
- 标准名称
- 别名

精确匹配：自动关联。  
高相似度：显示候选，由用户确认。  
未匹配：可创建新物料候选，不能自动创建。

## 19. 重复数据原则

> **禁止AI/算法自动合并主数据。**

模糊命中只能生成重复候选。合并时必须指定保留对象，并保存完整合并记录。

## 18. 检索技术流程

> 确认范围 → 文件状态过滤 → 元数据匹配 → 全文检索 → 语义向量召回 → 结果融合 → 重排 → 按文件聚合 → 真实原文片段 → 返回结果

文件检索只到“检索+重排”，不进入大模型生成。

## 19. 文件检索不调用外部大模型

普通搜索不得触发外部LLM。

建议通过：
- PostgreSQL全文检索
- pgvector
- 元数据索引
- 搜索排序服务

完成。

## 20. 语义检索安全约束

所有正式可搜索文件必须至少支持：
> 元数据 + 本地全文检索

如果使用本地Embedding，可覆盖所有文件。

如果Embedding是外部服务：
> 未获得外部AI授权的文件不得发送。

这类文件自动降级为元数据+全文检索。

## 21. 混合召回

候选集：
- Metadata
- Full Text
- Semantic

统一融合排序。

## 22. 排序原则

综合：
- 文件名精确匹配
- 关联对象精确匹配
- 标题匹配
- 标签匹配
- 正文关键词匹配
- 语义相关性
- 当前有效版本
- 更新时间

默认相关度排序。

支持：
- 相关度
- 更新时间新→旧
- 更新时间旧→新
- 文件名称

# 第四篇 《AI研发助手——AI问答详细功能设计》

**项目：** 杰事达材料研发系统  
**模块：** AI研发助手 → AI问答  
**版本：** V1.0-Draft  
**设计状态：** 可进入原型细化 / AI链路技术评审 / 前后端评审  
**本次范围：** AI问答页面、会话管理、检索范围、研发知识库RAG、数据中心结构化数据调用、实时互联网搜索、外部大模型调用、引用校验、回答展示、来源追溯、反馈、回答快照、项目沉淀及异常处理。

## 1. AI问答的产品定位

AI问答不是“接一个ChatGPT聊天框”。

正式定义：

> **面向材料研发工作的企业级证据增强问答助手。**

每个回答必须能够说明：
- 我依据了什么？
- 这些依据来自哪里？
- 以后还能不能看到当时依据的原始版本？

核心价值：

> **有企业数据依据、能回原文、能回原数据、能沉淀到项目并长期追溯。**

## 2. 本模块最终确认边界

| 事项 | 正式结论 |
|---|---|
| 大模型 | 只使用外部大模型 |
| 研发知识库 | 只使用已发布 + AI已授权 + 当前有效知识 |
| 数据中心 | 允许查询正式结构化数据 |
| 文件检索 | 与AI问答分开；文件检索不搜结构化记录 |
| 实时互联网 | 允许 |
| 联网方式 | 系统受控联网服务，不允许模型任意访问URL |
| 内部/外部依据 | 必须明确区分 |
| 普通数据权限 | 一期暂不做复杂ACL |
| AI安全门禁 | 必须保留 |
| 回答保存 | 支持完整AI回答快照 |
| 项目沉淀 | AI回答快照可加入项目资料参考 |
| 来源升级 | 不覆盖历史回答及历史引用 |
| AI输出 | 辅助结果，不直接成为正式研发结论 |

## 4. AI安全控制与普通权限的区别

一期暂不建设复杂组织/部门/项目/个人ACL，但由于只使用外部大模型，必须保留两类AI安全门禁。

### 4.1 知识文件

`AI使用授权`

控制：

### 4.2 数据中心

`AI数据可用策略`

控制：

这两个属于：
> AI外发安全门禁

当前有效V2与历史V1不一致时：

当前事实默认以V2为准，历史问题可引用V1。

- 回答不准确
- 引用不正确
- 来源不充分
- 遗漏重要资料
- 没有回答问题
- 外部资料质量差
- 其他

支持备注。

## 86. 反馈不能自动改业务数据

## 93. 停止生成

生成中按钮变为：
> ■ 停止

点击后状态CANCELLED。

## 94. 外部模型超时

提供：
- 查看检索结果
- 重新生成

## 95. 互联网搜索失败

内部证据正常时继续回答，并提示：
> 联网补充失败，本次回答仅基于内部资料。

状态PARTIAL。

## 96. 数据查询失败

知识证据仍可回答时继续，但明确：
> 部分结构化数据查询失败，本回答未包含该部分数据。

## 97. 内部知识检索失败

数据中心仍可提供事实时可继续回答，但不能假装已经查过知识库。

## 98. 上下文过长

不发送全部历史聊天。

采用：
- 最近必要对话
- 对话摘要
- 当前问题
- 当前证据

对话摘要不作为事实证据。

## 99. 对话上下文和证据分开

上一轮AI说过的内容不能自动成为新的事实来源。

本轮事实仍需K/D/E证据引用。

# 第六篇 统一产品原则

## 1. 文件不可覆盖

任何进入正式知识、项目参考、AI回答的文件版本都必须可追溯。

## 2. 正式数据不可静默覆盖

基础主数据保存Revision；配方/工艺/标准创建新版本；业务数据回原业务模块修改。

## 3. AI不能绕过业务系统

AI只能读取受控证据和调用白名单工具，不能直接读取数据库、MinIO或任意URL。

## 4. AI必须区分三类内容

- 内部知识
- 内部数据
- 外部参考

## 5. AI输出不是正式研发结论

AI回答、AI推断、AI建议均属于辅助信息，关键结论仍需人工确认。

## 6. 项目历史冻结当时证据

回答保存到项目时冻结：
- Question
- Answer
- FileVersion
- DataVersion / QueryResultSnapshot
- ExternalReference
- Model
- PromptVersion
- ScopeSnapshot

## 7. 文件检索与AI问答严格分工

> **文件检索负责“找到证据”**  
> **AI问答负责“利用证据回答”**
