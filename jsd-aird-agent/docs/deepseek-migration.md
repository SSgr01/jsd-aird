# DeepSeek Harness 接入

上游固定 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`（`0.2.2-rc.1`），使用独立 Node 24.11.1 和 pnpm 11.28.5。企业插件独立维护，不修改上游执行循环。保留现有未提交修改，不新增数据库迁移，本地 Flyway 关闭。

## 当前结构

企业登录和同域 `/agent/` 网关 → 原生 dsh 标准能力 → 企业插件 → Python 业务服务、Java 和沙箱。

| 所有者 | 职责 |
| --- | --- |
| dsh | 模型循环、会话日志、Inbox、计划、交互询问、标题、压缩、恢复、文件、技能、附件、预览与交付 |
| 网关 | 当前登录与会话归属、按组织和用户隔离 Host、DSH_HOME、附件和执行目录；内部启动令牌及 Cookie 不发给浏览器 |
| 企业插件 | 原生工具的沙箱桥、原生资料入口和业务视图、业务工具按需发现、模型与工具门禁、事件投影 |
| Python | 工具授权、证据与引用、正式报告核查和保存、成果登记、操作账本、幂等与未知结果对账 |
| Java | 企业权限、业务版本、检索、项目需求与资料关联、实验、草稿和成果权威存储 |
| 沙箱 | 无网络、非 root、只读根文件系统中的脚本、计算与 Office 执行回执 |

模型状态以 dsh 日志为准；业务操作结果以权威回执为准。日志外发、遥测、模型安装插件、宿主命令及任意系统目录访问关闭。会话、附件和业务资源在模型步、工具执行、恢复和读取时检查当前权限。失效身份不能继续调用模型或工具。

## 一个任务入口

企业预设组合固定上游的标准 blueprint，保留文件搜索、原生技能、询问、计划、网页工具、压缩与结果整理。独立快速问答预设、单次生成和禁用工具分支已移除。普通问答、研究及原问答 HTTP 地址统一使用同一 dsh 路径；简单问题直接回答，多步任务自主展开。原问答 HTTP 断开时取消对应 Run，包括任务准入和 SSE 阶段。

DSH Workspace 只管工作目录和会话成员关系，执行目录不等于问答模式或业务项目。企业资料通过原生附件或 `@` 随消息输入。默认按当前权限检索；用户的明确资料限制只绑定本次请求，不作为会话偏好继承。没有企业自建的资料范围、成果、计划或待发送面板，Inbox 是唯一待发队列。

## 模型和原生交互

部署默认通过环境变量初始化原生模型服务；后续配置和选择使用 dsh 的原生模型界面。密钥只在服务端保存，配置写入限管理员。主任务、标题和报告核查均经会话授权并记录各自用量。标题失败不阻断任务，手工标题不被覆盖。

当前本地目标路由为 `deepseek-v4.1-flash-1017`，走已配置的 DashScope Messages 网关，原生 DeepSeekAdapter 已实测工具调用、推理历史和缓存用量。自定义型号不借用未验证的 system/tool update 协议能力。

自定义型号的图片能力由实际路由验证后声明，可使用 `JSD_AIRD_DSH_INPUT_MODALITIES=text,image` 初始化。2026-11-06 使用原生附件存储和 DeepSeekAdapter 实测识图成功：Files 端点 404 后，上游自动回退至 Base64 图片块，Messages 200，正确识别颜色、图形及数字。没有额外 OCR 模型。该结果只适用于此次验证的接口和型号，不能推定其他路由。

新用户默认完成后折叠过程并只保留最终回复，已有显示偏好继续使用原生设置。企业工具用原生 presentation 扩展展示简短结果和原文入口。原文复用原生 Markdown、侧栏和 PDF 组件；企业插件只负责当前权限、固定版本与位置映射。

原生 Inbox 负责排队、编辑、取消、插话、自动发送和日志恢复。固定上游缺少排序与放回输入框，企业插件仅在原生输入区补这两个动作：排序使用一次原生 Inbox splice，保留消息身份、附件与日志；纯文本放回通过原生 draft initialization 追加，保留现有文字和引用，先保留输入再移出队列。队列顺序或文字已变化时拒绝操作；响应未确认时保留输入并提示核对，不自动重试。含附件消息继续使用上游支持的动作，不将附件静默转换或丢弃。网关重启后通过原生 resolveAgent 恢复队列，不启动模型轮次。

网页搜索使用原生 `web_search`，由 `ctx.web` 接入已有 Java Tavily 后端。搜索凭据不借用聊天网关密钥，也不发送至另一个默认端点；未配置时如实不可用。每次查询绑定真实 Session/Turn/Call，经过权限、预算和操作账本。网页抓取继续使用上游的受限 HTTP 后端。论文发现、书目核对和许可全文获取仍是独立专业工具。

## 研发数据和专业技能

- 原始附件可直接用原生文件及脚本读取；已有解析补充目录、章节、页码和表格。解析服务临时故障不阻断原始文件，权限拒绝仍停止。
- `retrieve_context` 复用现有联合检索，使用原生任务已经规划的查询，不再隐藏调用另配的查询改写模型；`query_structured_data` 直接复用已有结构化读取服务，返回字段、数值、单位和相邻条件。文件歧义、截断与比较条件明确返回。
- 项目只读。阶段和任务沿真实项目关系读取；`get_project_records` 沿已存储的项目需求和资料关联读取，来源回读重新检查关系、权限、版本及正文哈希。项目实验用真实 `project_id` 关联，名称相似不等于业务关联。
- 实验当前两个标准模板直接复用已发布字段契约、规范化及 LabWorkbook 结果；新增模板不建白名单框架，保留未知字段。实验、版本、样品组成复合身份，配方、工艺、方法、条件和结果对应保存。缺失、未测、零值和不同单位不能混用。
- 实验草稿沿现有分类、模板版本、编号、规范化、审计及幂等逻辑创建，允许无项目实验。不猜日期、配方和条件；缺少业务必填信息才询问。正式提交、审核和发布留在原流程。
- 固定版本读取包含当前草稿，不将已发布版本历史列表当成全部可读版本。已确认的草稿创建后重新读取受影响项目、阶段、任务和草稿；替换当前证据时将旧证据留作审计，不重放写入。项目来源授权检查当前权限、真实关系和实体版本，正式引用仍校验完整正文哈希与摘录。实验数量等派生摘要变化不能被误报为实体版本变更。
- 工具对模型主要返回正文、表格、简短来源和分页，完整权限、来源与哈希保留在账本。实验搜索只返回身份摘要；明细将样品身份声明一次，以表格保留数值、状态、单位和位置，按可读内容长度分页。通用长结果交给 dsh 整理，不再写入模型无法访问的 Python `input/results`。专业指导通过原生技能按需加载，不再通过 `skill_read` 注入重复的 Office 或研究指南。
- 可选 `evidence_score` 与正式报告核查都使用当前会话的 dsh 模型服务，逐次授权并计量。证据评分按真实 ID 严格校验响应；错误 ID、非法评分或服务故障不记为内容不合格。Control 不再维护 PaperQA/LiteLLM 的另一份模型密钥和路由。
- 普通回答检查引用与来源，不强制研究矩阵、正式报告核查和保存。正式报告保存前执行核查；内容不支持、核查服务故障和保存失败分别记录。技术故障不得永久记为内容不合格。
