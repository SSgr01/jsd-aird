# 问答与研究共用证据协议

快速问答仍由 Java 完成一次固定检索后生成；研究仍按工具循环执行。两个入口和会话存储不关联。

## 数据与引用

- `SourceRef` 固定来源类型、文档、版本、来源节点、原文哈希和定位；Python 定义位于 evidence/models.py。
- 规范证据包含 `evidence_id`、`text`、`source`，可附节点位置、命中角色和评分。ID 保持原有算法：规范 SourceRef 的排序 UTF-8 JSON SHA-256 前 24 位，加 e 前缀。
- 原文哈希在登记前校验；登记不增加全文覆盖，不缓存授权。既有 quote handle 的算法、原文跨度和来源对象保持不变，生成与解析统一位于 evidence/quotes.py。
- 固定问答 PreparedQa 为候选证据提供规范 ID，控制层登记别名到 ID 的映射；K/D/E 是本轮展示别名，不是全局来源身份。研究继续使用 `[E:证据ID]`。
- 问答 SSE 事件和已有引用字段保持兼容，新增 `evidenceId`、`source`。历史引用没有新字段时继续使用旧预览／下载适配器，不猜测来源、不回写历史。
- 共用生成校验只保证引用身份合法，不保证事实支持或科研正确性。

Java/Python/TypeScript 共用 contracts/evidence.json 脱敏样例。Java 和 Python 校验权威 ID 与哈希；浏览器接收服务端 ID，不依据 UI 来源 key 重新生成身份。

## 检索与展示边界

Java 检索公共组件统一数据命中、歧义、公式核对、压缩、重排适配和来源投影。问答上下文与候选证据来自同一结果，不二次检索；固定来源、自动发现、私有搜索和历史发布检索策略各自保留。

两类页面继续共用 AiConversationWorkspace，通过各自适配器使用统一正文、流式文本更新、输入、恢复提示和来源详情组件。研究的计划、队列、审批及成果区独立保留。

`POST /api/v1/assistant/sources/authorize` 在每次打开证据时重新检查当前身份、ai.use 和资料权限；文献来源还验证固定版本、原文哈希和定位。该接口不检索、不授权新范围、不返回用户无权访问的正文。坐标比较接受 JSON 等值数字 1/1.0，但不接受不同坐标、字符串替代数字或其他元数据变化；这不改变权威哈希或原文。

没有 quote handle 时只展示节点预览；有同源句柄时展示精确跨度。未授权前隐藏缓存片段，失败后显示不可访问。
