# 实验文件转换与人工核对

在电子实验记录本的“实验数据导入”中选择“专家转换”，选择测试或合成实验标准模板及实验分类，批量提交 XLSX / DOCX 原件。单份最多 8 MiB，每批最多 100 份。上传后原件持久保存；启动失败可从同一条记录继续启动，不必重传。

公司技能 `jsd-experiment-converter` 随企业插件发布，实验记录助理和普通助手可发现同一共享技能。脚本、参考资料和两份空白模板从受管技能包复制到独立任务目录；历史业务样例计划留在本地，不随代码或运行资源分发。不依赖桌面路径，不增加宿主命令执行或第二套调度器。

每个原件一个原生专家会话，通过原生准入和 Inbox 执行。`experiment_conversion(action=source)`取得本人原件，并准备当前任务的工作副本；模型负责语义映射，随包 Python 负责写入和核验。陌生文件仍需模型判断，旧计划只有源和模板指纹均匹配时才能重放。模板指纹不一致时不会按文件名套用。

使用原生 `artifact_save` 分别登记 XLSX、映射计划 JSON、verification.json，取得三个真实成果 ID；`present`可展示成果。`experiment_conversion(action=stage)`读取已登记、本人可访问且有当前导出权限的成果，复核实际字节、源、计划、模板及结果指纹，然后建立 `EXPERIMENT_DRAFT` 导入任务。该工具不提供确认或发布动作。生成结果和历史核验报告不因人工修改而覆盖。

上传历史显示原件、处理状态、专家会话和核对入口。核对工作台显示未落位项及源合计冲突，可下载原件对照并使用现有编辑、关联项目及“完成数据核对”功能。机器 `validated` 和冲突稿 `review_required` 均为待人工核对；确认导入后创建实验草稿，正式发布仍沿用原流程。单文件失败保留原因，其他文件独立继续。转换队列当前只展示本人的最近 100 条记录。

权限沿用 `ai.use`、`eln.upload.view/create`，转换来源随实际读取进入成果的服务端来源范围，下载生成成果还需当前 `eln.view.export`。本人原件及任务归属在服务端核对，后台简报授权不能调用转换。任务原件、结果成果、计划和报告分别留存于原有文件存储与新增的 `data.experiment_conversion` 关联表。

部署需执行 `V117__experiment_conversion_queue.sql`，构建企业插件并更新 API、Control、Gateway。原生工作台按源文件独立保存执行目录；沙箱已有 openpyxl，不需新增 Python 依赖或镜像。技能附带的模板是本次发布的固定资源，导入仍按所选系统模板版本检查结构兼容性；不兼容时保留待处理，不能声称已支持任意公司模板。XLS / DOC、PDF、图片暂不进入本转换入口，原有导入入口继续保留。

转换结果的模板解析沿用现有异步 worker；本地可用 `scripts/dev-harness.ps1 -Service worker -EnvFile .env` 启动。未启动时原件和成果仍已保存，但核对工作簿会停在排队；不能把排队说成已准备好核对。

不得将脚本回归、一次转换成功或格式兼容当作语义映射已完成人工核对。真实模型、权限撤销、批量恢复与最终工作台还须分别验证，具体本地检查结果见实施记录。

## 服务器文件夹模式

此模式复用现有“实验记录助理”对话，不增加页面、上传入口或人工审核状态。只写服务器结果目录；不生成实验、导入任务或业务附件。原上传转换模式继续使用原接口。

服务器按 Linux 部署，统一固定目录如下；资料别名固定为“历史实验资料”。这些位置由实施人员安装和配置，客户无需选择目录或填写技术参数。

| 用途 | 固定服务器路径 |
| --- | --- |
| 原始资料 | `/srv/jsd-aird/experiment-history/originals` |
| 标准模板 | `/srv/jsd-aird/experiment-history/templates` |
| 转换结果 | `/srv/jsd-aird/experiment-history/results` |
| 后台目录配置 | `/etc/jsd-aird/experiment-conversion-roots.json` |

部署管理员将 `deployment/experiment-conversion-roots.example.json` 安装到上述配置位置，仅替换真实组织 ID 和获准管理员用户 ID，三个资料目录使用样例中已确定的路径。Control 后台代码默认读取 `/etc/jsd-aird/experiment-conversion-roots.json`，安装到固定位置后无需另填路径环境变量；默认文件尚未安装时不授予任何目录访问权限。部署新版本后重启 Control、DSH 网关和原生 Host 使其加载目录能力。已有部署的 `JSD_AIRD_HARNESS_CONVERSION_ROOTS_FILE` 显式配置仍优先，指向缺失文件会明确报配置不可用，不回退到其他目录。目录必须是 Control 服务所在 Linux 服务器可访问的路径；容器部署将上述原始资料和模板目录按同路径只读挂载到 Control 容器，结果目录按同路径可写挂载，配置文件按同路径只读挂载。不要把这些资料目录挂载到模型沙箱。

Linux 目录包已包含上述三个目录，以及空白 `test.xlsx`、`synthesis.xlsx`。原始资料目录支持 XLSX、XLS、DOC、DOCX，可保留客户原来的子目录。原始资料和模板给 Control 服务账号只读权限，结果目录给写入权限；配置文件给服务账号读取权限。禁止链接、目录联接和路径越界。示例组织 ID 和用户 ID 是占位值，由实施人员替换；服务器路径已经统一确定。

用户在现有实验记录助理对话输入：

> 转换服务器“历史实验资料”，逐份判断，结果只留文件夹。

专家通过 `folder_conversion` 的 list、start 启动；首次启动立即返回批次 ID。扫描、校验值计算在后台进行，扫描完成后固定本批清单，不监控后续新文件。可继续说“查看这批进度”“暂停这批转换”“继续这批转换”，分别使用 status、pause、continue；扫描时暂停会在扫描完成后停止派发。暂停不打断已开始的文件。status 每页最多 30 项，不把五千份正文装进上下文。关闭浏览器后，网关通过批次授权恢复派发；服务重启仍使用持久化的清单、原生会话与 Inbox 请求 ID。

每批至多派发两份，仍受现有用户、组织和全局任务限额限制。每份原件复制到独立任务工作区，DSH 原生主代理判断类型并生成该文件自己的映射；不自动复用另一份文件的语义映射。XLS/DOC 通过现有严格 Office 转换服务生成副本；不使用预览降级结果。大于 8 MiB 的单份原件或副本、加密、损坏、无法辨认类型及缺少必要信息的文件单独记录阻塞。仍保留现有沙箱 50 文件/10 MiB 的总传输限额；不增加 OCR。

结果结构：`结果目录/批次ID/原相对目录/原文件名含扩展名.converted/`，包含 `result.xlsx`、`mapping.json`、`verification.json`。失败说明放在同批 `.errors/文件ID.json`。旧格式的固定工作副本及其校验元数据放在同批隐藏 `.dsh-state/文件ID/`，恢复时复用并核验，避免重复转换造成副本字节变化。报告保留原件、副本、模板、映射、结果的校验值及真实沙箱执行回执，列出未落位数据、冲突与限制，不记录人工核对人、审核状态或审批信息。文件夹结果仅是转换稿，仍由客户自行逐份检查。

导出必须匹配真实、成功的沙箱回执，不能用模型提交的“已完成”代替。源文件或模板变化时该项拒绝保存；已有结果被外部修改时拒绝覆盖。批次还固定脚本资源版本，版本变化时停止继续派发，需用新批次处理。转换失败不影响其余文件；修复来源后可明确启动新批次，旧批次及结果保留。

运行清单和断点保存在现有 Control 技术记录 `folder-batch`、`folder-item`，不属于实验业务记录。应同时备份 Control 运行库和结果目录；只复制结果目录不能恢复原生会话和任务断点。文件夹后台授权独立于研发简报与个人记忆，绑定组织、用户、批次和配置目录，每次续签重新核验 IAM 与目录配置。移除该管理员或目录配置即可停止后续授权。

验证范围包括五千份模拟文件的扫描及有界派发、四种扩展名、严格旧格式适配、来源变化、越界、结果回执和重复保存。真实 XLS/DOC 的高保真效果依赖部署环境的 Office 隔离服务与 LibreOffice，正式全量处理前应使用客户样本验证。
