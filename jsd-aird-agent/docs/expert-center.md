# 杰事达 AI 员工专家中心 · 第一期

本期将公司专家接入现有 DSH 工作台。专家提供专业职责和工作方法，使用同一个原生主 Agent 执行循环、会话、模型选择、输入附件、文件与停止继续功能。

## 产品范围

- 8 位公司预设：项目助理、客户跟进助理、实验记录助理、检测质量助理、生产库存助理、材料研发参谋、技术资料助理、数据整理助理。
- 侧栏的“专家中心”进入独立主页面：公司专家卡片、名称/描述/能力搜索、领域筛选、全部/常用/最近视图。
- 卡片显示角色标识、领域、简介和能力标签，底部只保留召唤入口。点击角色查看详情、职责、发布版本和任务示例；可直接召唤或设为常用。
- 会话输入区显示当前专家，点击展开原生快捷菜单；可搜索、从常用及最近中选择，或进入完整专家中心。
- 召唤创建原生会话，不自动发送消息。点击示例填入可编辑草稿，已有文字与附件保留。切换专家创建新会话；同一会话固定一个角色及发布版本。
- 常用偏好按组织和用户持久保存。最近最多展示 5 位不同专家，来源为最近更新的 100 个本人未删除业务会话。会话分支继承原专家版本。

暂不提供个人创建编辑、会话中自然语言配置、分享、复制定制、专家团；不为每个业务页面固定一个员工，不新增自动化功能。

## 共享技能与专家业务配置

新增发布版本 2，保留版本 1 及既有会话快照。8 位专家共享 14 个原生 Skill，不为每人复制执行逻辑。执行相关专业任务前提示主 Agent 按任务读取匹配的 Skill；沿用原生加载与执行循环，不新增强制编排器。

| 专家 | 默认共享技能 |
| --- | --- |
| 项目助理 | 项目诊断、会议行动项整理、工作简报编制 |
| 客户跟进助理 | 客户需求整理与比较、会议行动项整理、业务回复起草 |
| 实验记录助理 | 记录整理与核验、实验对比 |
| 检测质量助理 | 检测质量核对与文件草稿、记录整理与核验 |
| 生产库存助理 | 生产库存与数量核对、记录整理与核验、工作简报编制 |
| 材料研发参谋 | 配方分析、实验对比、竞争假设与实验设计 |
| 技术资料助理 | 文献调研与研读、论文专利与技术路线比较 |
| 数据整理助理 | 表格整理、记录整理与核验 |

会议行动项、记录核验、工作简报由多个专家共用。业务关联、异常证据与重复冲突检查并入对应工作流程，不把每个缺项拆成 Skill。Skill 是平台维护的步骤指导，实际查询与计算仍通过原生工具；模型是否完整执行流程仍需真实业务验收，不能把增加技能文件当成所有业务已接通。

每个版本保存 `work_config`，从受信 Java 目录读取，随会话和 Run 固定，并注入专业任务说明：

- `scope`：业务对象类型、当前任务选择原则、固定对象引用；当前固定引用为空。业务类型是工作关注点，不是自动查询过滤器或权限授予，实际对象按任务解析并受服务端权限约束。
- `checks`：必填字段、组合身份字段、默认单位、判断规则和参数。实验默认核验日期、操作者、配方版本、原料批次、工艺条件、样品编号，默认质量 g、温度 ℃。实际业务模板要求的额外字段须一起核对。
- `delivery`：有编号和版本的通用交付结构、章节和表格列，状态为草稿。按任务选用，不要求每轮都生成文件，不冒充公司正式模板。
- `pending` 和空参数：待提供的公司规范，例如规格版本、容差、修约、编号、预算、COA 模板和复核流程。未知规则不能由模型自行补成公司标准。

详情弹窗以只读方式展示工作范围、共享技能、重点核验、默认单位、检查规则、默认交付及待提供项。公司通过发布新目录版本维护，不提供个人编辑、自然语言修改或持久化本次任务规则。

## 确定性核验工具

Control 的 core 能力包版本升为 3，新增三个只读工具，沿用工具发现、现有授权、调用账本、重放及撤权检查。只处理调用方提交的输入，不查询额外资料或扩大数据权限：

| 工具 | 已实现的确定性行为 | 限制 |
| --- | --- | --- |
| `record_validate` | 自动叠加会话固定专家必填字段与组合身份；检查缺项、精确重复、同标识冲突，保留来源和原值 | 不是模板格式或真实业务关联验证；未配置主键不自动合并；疑似重复由流程识别候选 |
| `quantity_check` | 十进制单位换算；实际−理论差异及差异率；零理论量返回未定义；有明确来源的百分比容差才核对容差 | 不猜密度、有效含量或包装换算；收发存平衡由原生代码按实际完整分项计算；未给容差不判可接受 |
| `specification_compare` | 检查规格来源与版本、双方方法条件、上下限及包含边界；同量纲换算后按原始精度比较 | 字面方法条件不同则不可比；缺依据待确认；需标准修约则交复核，不做正式放行 |

支持质量 mg/g/kg/t、体积 mL/L、长度 mm/cm/m、压力 Pa/kPa/MPa、黏度 mPa·s/Pa·s、比例 %/1、温度 ℃/°C/K。未知单位和跨量纲返回不可比；温度不按投料差异率处理。数值使用受限长度的十进制字符串和 Decimal，计算精度 60 位有效数字；不为限值核对擅自修约测量值，循环小数差异率按该精度表达。

工具结果保留输入、输入哈希、引擎版本、专家版本和草稿状态，并明确输入未经来源验证。它们能证明“这些输入按这些规则算出的结果”，不能证明输入事实、所选规格适用或业务关联真实；专家仍须先读取获授权记录并引用底层证据。COA 仅出草稿，正式复核、签章、发布流程尚未新增。

## 定义、绑定与权限

Java 的 `ai/expert-presets.json` 是公司角色目录，`ExpertCatalogService` 每次读取调用既有企业使用授权。没有个人写入接口。`GET /api/v1/agents/experts` 和 `/{id}` 提供受权读取，内部 `expert_catalog` 供 Control 核验。

发布时向 `versions` 增加新版本并更新 `current_revision`，已发布版本内容必须保持不变，也不能删除仍有会话引用的版本。新增会话使用当前版本；已有会话保存角色快照并继续使用原版本。`enabled=false` 禁止新召唤和继续执行，历史仍可查看。

浏览器只能使用 `list/session/pin/summon`。召唤由企业插件先核验专家，再创建原生 `enterprise` 预设会话，通过可信 Control 路径保存绑定，成功后才返回给用户界面。浏览器传入的任意 instructions、skills、preset 均不能成为角色定义。原生会话分支返回前补齐角色绑定。

Control 复用 `agent_runtime.harness_records` 保存会话专家快照和本人常用偏好，无新增数据库迁移。首次及后续 Run 均从会话继承角色，执行时重新核验停用状态；现有 CORE_INSTRUCTIONS 和企业权限优先于角色说明。已有普通对话或已绑定专家的对话不可被改绑。

专家不授予新工具、业务数据或系统权限；角色中的技能列表指向共享原生 Skill，并在相关任务前提示读取。未接通或无权访问的业务仍按现有机制拒绝，专家应说明限制，不能把拒绝当作空结果。单个专家不要求创建子 Agent；专家中心不实现委派或团队编排。

## 验证

使用 Node 24 执行 `jsd-aird-agent/deepseek` 下 `node --experimental-transform-types --test test/*.test.mjs`。157 项通过，包括召唤顺序、禁止浏览器改绑/配置、分支继承、既有会话生命周期和网关策略。

Control 在独立的 `jsd_aird_agents_expert_test` PostgreSQL 库中运行 business_checks、experts、tool_discovery、dsh_session_policy、session_deletion、business_data、business_dispatch、business_context、runtime_context 九组测试，143 项通过。覆盖数值精度、单位量纲、零分母、上下限、方法条件、缺失依据、重复冲突、固定配置、版本继承及授权撤销。计算工具在真实调用账本中的执行与幂等重放也已验证；不启动模型。原共用测试库缺少 `harness_calls.arguments` 等本分支使用的字段，扩大回归曾因此失败；未修改共用库，改用新库迁移后通过。

Java `mvnw.cmd -q -Dtest=ExpertCatalogServiceTest test` 通过（2 项），包括读取授权、配置深拷贝、历史版本及 null revision 的当前版本解析。扩大执行的 `ArchitectureRulesTest/ModuleBoundaryTest` 仍报告未修改模块中的 rnd、iam 等既有依赖违规；本功能未更改这些模块。

浏览器使用实际专家 UI 源码与原生 Modal/Menu，在独立组件验证页中检查搜索、详情、常用、示例、切换保留草稿附件、失败重试和 1440/768/390 像素布局。新增只读配置已检查 1440/768/390 像素弹窗布局及滚动，无水平溢出。验证页的业务 API 和会话服务使用测试替身；尚未完成带登录、真实后端和模型的整栈端到端验收，也未部署到现有运行服务。
