# Harness 步骤绑定与进度投影

步骤注册使用 `binding_protocol: 2`。服务端返回 Run ID、轮次、能力包和自动化标记，以及发生变化的 `tools`、`active_tools`、`instructions`、`context`。这些字段分别通过 `binding_etags` 校验；证据正文、检索快照和完整执行账本保留在 Control，由已有资源接口按需读取。未声明协议的调用者仍获得兼容响应。

`ownership` 在完成原有权限校验后只返回授权回执；恢复接口仍按需返回完整恢复状态。

插件在同一轮次回传收到的 etag 和 `known_citation_evidence_ids`，服务端仅生成新增证据及其 quote 别名的链接。引用确认游标独立于工具结果附带的链接，避免漏发 quote 别名。新输入、新轮次及恢复后的首次注册请求完整绑定。模型上下文仍保留已授权的输入，刷新当前业务状态。增量游标只控制传输，所有原有授权与工作准入仍执行。

普通原生事件在 150 ms 窗口合并为最后一个序号及轮次、步骤，不再次传输请求上下文或工具结果。Control 只读取映射字段并更新 Conversation 的 `dsh_seq`，不加载或更新完整 Run。`assistant/message`、`user/message`、`turn/end` 和 `agent/inbox/spliced` 保持原内容与顺序，前置刷新普通进度。重要事件失败会阻止后续投影越过它，并阻止下一步骤或完成检查；恢复时从原生持久日志重放。

旧界面的流式投影只发送正文增量，最多每 500 ms 排入一批；队列积压时继续合并同一批。原生订阅仍收到所有流帧。步骤绑定、停止、删除前刷新并等待投影；业务工具写入和回执继续同步持久化。取消、失败、文件交付意图和最终文本仍按原业务流程处理。Run 的 `dsh_seq` 保留最近重要事件，Conversation 的游标包含普通进度；恢复时可能多重放普通事件，由会话游标去重。

## 阶段计时

设置 `JSD_AIRD_HARNESS_STAGE_TIMING=true`，并同时刷新 Control 和 Gateway。默认关闭。服务端通过 `HARNESS_STAGE` 日志及 `Server-Timing`、`X-Jsd-Trace-Id` 响应头记录 HTTP、连接池、事务锁、账本读取和更新、业务主机 HTTP 等耗时。插件将绑定总时间、绑定等待、投影队列等待、请求编解码和传输字节写入 Host 的结构化诊断日志，不受原生日志 INFO 级别过滤影响。

日志只包含阶段、内部标识、次数、时间和大小，不记录正文、票据、请求参数或来源 URL。数据库读取/更新计时覆盖 JSON 适配与结果解码；事务锁计时还包括首条 SQL 的事务开启和往返，不等于纯服务端锁等待。直接 SQL、事件写入、提交、响应序列化等有一部分落在未细分时间中。并行请求和队列等待会重叠，累计值不能直接解释成墙钟时间；需要按同一 Run 和具体步骤区间关联分析。
