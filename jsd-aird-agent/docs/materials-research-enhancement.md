# 材料研发文献研究增强与对照评测

复杂材料研究沿用同一个 DSH 执行循环及现有企业工具，增加问题组织、条件比较、反证核对和定向补查指导。普通单篇研读和数值查询直接查证；研究维度由用户目标与实际文献决定，不使用固定的材料、机理、测试、工程栏目。

## 行为变化

- 跨文献比较、路线选择、复合性能判断和工程适用性评估先加载现有 `literature-review` 技能。材料、制备、性能、成本等只在影响本次判断时纳入子问题。
- 保留实际用户目标，按子问题取得原文；关联对象、指标定义、单位、计量基准和测试条件。区分现象演示、定量性能及器件验证，不能拼接不同论文各自测过的属性。
- 核对关键结论的支持、反例与限制；重复转述同一实验不算独立验证。遇到矛盾先核对条件，不强行平均或制造共识。
- 工程建议与已测事实分别表达。审查发现关键缺口后优先补读已有来源，在获准范围内定向检索；同一缺口补查两轮仍无新证据时说明限制，不反复重查或提高预算。
- 中间依据复用现有证据矩阵及进度笔记。只有用户要求时创建实验草稿、交付文件或保存正式报告；正式报告继续执行原文核查及保存回执要求。

文献能力版本升至 `5`，新会话采用新的能力指纹。技能为完整内联正文，不引用不可访问的宿主脚本，不新增子代理、搜索服务、数据表或另一套模型循环。

## 可复用评测入口

使用 `scripts/local/compare_materials_research.py`，先运行 `baseline`，修改指导并重启本地 Control 与网关，再运行 `enhanced`。同一输出目录冻结题目、重复次数、并发、采集期限及非敏感模型配置；两组使用独立新会话。参考答案、原文和评分不进入模型请求。

```powershell
$evalPython = '.\jsd-aird-agent\control\.venv\Scripts\python.exe'
$evalCases = '.runtime/materials-research-ab-20261112/cases.json'
$evalOutput = '.runtime/materials-research-ab-20261112'
& $evalPython scripts/local/compare_materials_research.py run --cases $evalCases --output $evalOutput --variant baseline
# 切换被测版本并重启服务，保持模型、资料及预算相同。
& $evalPython scripts/local/compare_materials_research.py run --cases $evalCases --output $evalOutput --variant enhanced
& $evalPython scripts/local/compare_materials_research.py bundle --cases $evalCases --output $evalOutput
```

凭据取自进程环境或本地 `.env`，不写入题目和报告。整组共用一次登录，避免同账号并发登录替换会话。评测通过正常设置接口暂时关闭记忆读取和自动采集，结束或异常时恢复原设置；其他使用该账号的对话也会暂时受此设置影响，应在该账号空闲时运行。中断后先核对原任务和记忆设置，不能盲目重放。

输出包含两组指导快照、题目摘要、任务与事件记录、原生主模型用量、隐藏组别的答案包和单独的组别映射。核对成功率、关键事实、问题覆盖、证据与可比性、不确定性及决策价值；缺少账单时费用记为未知，不能把缓存 Token 与未缓存 Token 按同一价格估算。

## 本次对照

2026-11-12 使用六类材料研发题，各重复两次：多文献承载路线比较、低温与自愈性能的联合判断、涂层工程外推、错误前提核对、恢复时间查证和简单层厚提取。原件及全部逐题记录留在忽略目录 `.runtime/materials-research-ab-20261112/`。这是已有原件上的开发对照，不能称为独立验收集或统计意义上的质量证明。

两组使用相同的实际主模型 `deepseek-official / deepseek-v4.1-flash-1017`、固定资料、预算和独立新会话。原生记录确认两组复杂题均加载对应技能，能力版本由 4 变为 5。记忆读取与自动采集在测试期间关闭，结束后已恢复原值。完整问题、24 份执行记录、评分理由及答案对照见本地 `.runtime/materials-research-ab-20261112/report.md`。

成功率观察值上升，但内容质量没有显示提升，不能将本轮标记为“质量提升已验收”。总 Token 增长主要来自缓存读取；没有实际账单，费用未知。原版有一次执行结果隔离且没有答案、两次最终引用修复失败；增强版仍有一次引用修复失败。失败全部保留，已有草稿的内容单独评分，不能当成成功交付。

主要问题仍是未稳定遵守原文条件：将装夹另需数分钟的流程简化成约 5 分钟恢复，将单个时间点恢复率外推成永久损失，以及在简单厚度查询中主动补充错误的总厚。两组对跨体系性能不能拼接、划伤不等于磨耗等判断原本就较好，不计为新增能力收益。下一轮应优先验证结论与原文条件对应及数值计算，而非继续增加流程长度。

评分由本次实现代理逐条对照原 PDF 完成，每项 0–2 分：事实准确、问题覆盖、证据与可比性、不确定性及决策价值。评分前已见部分组别，隐藏组别答案包只供复核，不代表独立盲评。测试按原版、增强版顺序执行，没有随机交错；每题仅两次，不能据此证明成功率因果提升，也不能据内容分的小幅下降推断普遍退化。初期并发登录替换会话的调试记录独立保留，修复测试器后重新跑完整原版，未计入正式 24 次。

## 后续链路审查更正

同日[完整链路审查](materials-research-chain-audit.md)发现：JSD 绑定只返回 CORE，文献能力入口指导及详细共享回答规则没有按设计送入系统提示；新技能正文确实加载。上次 literature 4→5 还意外绕过了三个仅匹配版本 4 的读取/报告核查分支，因此不能把本轮称为完整增强方案或纯提示比较。上述分数保留为当时两个实际版本的观察结果，不能把差异全部归因于指导长度或模型能力。

本轮已修复三个版本分支，并增加 16 项版本协议测试；相关测试合计 136 项通过。该修复发生在旧 A/B 之后，未重载服务或做新质量对照，不覆盖旧测量、评分及配置快照。普通回答事实核对、指导送达和引用修复链路的后续优化见审查文档，尚未宣称收益。

随后已按用户要求修复指令送达与引用交付：共享规则从实际包资源读取，所选能力指导进入 JSD 绑定；沙箱可用性按配置声明；引用修复按服务端剩余额度继续，每轮刷新诊断，提示要求正文不附加坏句柄的修复说明。独立数据库上的相关后端 192 项、Node 定向回归 17 项通过。详见[审查文档的后续实施记录](materials-research-chain-audit.md#后续实施指令送达与引用交付修复)。旧结果及其限制保持不变。

## 重启后的实际验证

同日已重启 Control 与 DSH Gateway，并将工作台实际模型改为 `qwen3.7-flash-2026-07-15`。原生用户默认模型会覆盖部署默认，当前管理员覆盖已同步。原先继承的256000输出上限超出Qwen接口允许范围，已显式改为131072；修正后连通检查与正式模型收据均确认Qwen。Docker沙箱健康可用。

六题各两轮共12次，11次成功交付、1次最终引用失败。原生日志确认12次共享规则与文献能力入口送达；复杂题6次中4次实际加载技能。4次自然引用修复中3次成功；失败题确实使用了两次模型额度，第二次修复分支已触发，未以放宽校验掩盖失败。内容均分5.67/10、交付均分5.17/10，平均任务耗时117.9秒。科学条件误读、过度否定和简单取数遗漏仍存在，不能宣称质量提升已验收。
