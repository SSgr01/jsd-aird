# MinerU 超时续取与处理状态

## 部署

先停止导入脚本并停止旧 Worker，避免旧进程继续重复提交任务。
在项目数据库执行 `jsd-aird-api/src/main/resources/db/migration/V120__mineru_task_checkpoints.sql`，
再更新并启动 API、Worker，部署新版前端。手动执行迁移时使用 `psql -X -v ON_ERROR_STOP=1`。
V119 是独立的同名文档修复；若尚未执行，也须按原部署说明执行。

## 行为

- 每个文档版本、源文件内容、分片、远端地址、模型及有效 OCR 配置都有独立断点。
- 提交后立即保存批次与上传地址，上传完成后保存状态。Worker 重试或重启后复用批次；
  已上传文件不会再次上传，已完成批次直接获取结果。
- 远端明确失败后，下次允许提交新批次；超时或查询网络错误保留原批次。
  批次失效、查询鉴权失败不会被悄悄转换成重新提交。
- 对旧版记录，普通单文件可从同版本、同 OCR 模式的 MinerU 超时解析记录续取批次。
  旧版分片记录无法可靠还原每个分片的编号，不自动采用该记录。删除文档后也无法恢复其断点。
- ZIP、Markdown、图片资产的派生文件名最多 260 个 Unicode 字符，保留结果后缀；
  过长资产后缀使用摘要缩短。原标题不变。
- 详情页每 3 秒刷新活动任务，显示远端排队、远端处理、结果处理、等待重试或终止失败，
  并提供 MinerU 批次编号。远端状态是最近一次查询结果，不是远端的实时推送。
  多分片时显示最近更新分片的状态。5% 本地进度不代表远端页数进度。

## 验证与续跑

在详情页或 Worker 日志中核对 `Resuming MinerU batch` 与批次编号；
超时后重试应沿用同一批次，不再出现同文件的重复提交。
部署不会自动重启已经终止的任务。修复后用原 manifest 和 `--retry-failed` 续跑，
或在页面重新解析。已删除文档的失效 manifest 记录需先单独处理。
这次修复避免重复解析并准确呈现状态，不保证远端排队或计算更快。
