## 耗时、Token 和缓存

以下是本机单次验收观测，包含服务与模型路由当时的状态，不是稳定性能基准。

| 操作 | 附加耗时 | 实际生成模型用量 |
| --- | --- | --- |
| 新会话偏好文档快照 | 125 ms | 0 Token；直接读取已有文档 |
| 冷 Recall | 6,156 ms | API 不提供 embedding / reranker 用量，待对账 |
| 深层 Reflect | 25,468 ms | 输入 10,456，输出 470，总计 10,926，缓存 0 |
| 工作台关闭后的自动整理 | 6,348 ms（提交至完成） | 输入 3,230，输出 89，总计 3,319，缓存 2,816 |
| 工作台手动保存偏好 | 6,887 ms | 输入 3,245，输出 176，总计 3,421，缓存 2,816 |

冷 Recall 曾超过 3 秒，因此默认超时改为 8 秒；偏好快照使用独立文档读取。召回或验证故障不会让普通请求无限等待；无法验证的已有记忆会停止使用。正文快照保守限制在 800 UTF-8 字节内，不把估计当作精确模型 Token。

包含两项记忆的新会话首轮总用量约 9.6K Token，原生显示缓存命中约 86%；另一次单轮约 9.2K、缓存 87%。这些包含系统、工具、用户输入及输出，不能将差值单独归因于记忆。计量未知时保留待对账；计量故障不重新摄取正文。
