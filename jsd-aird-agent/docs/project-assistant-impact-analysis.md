# 项目助理跨任务与实验影响分析

日期：2026 年 11 月 17 日

## 本次行为调整

用户在工作台选择项目助理，询问项目进展、卡点、需求变化或下一步时，分析应沿“客户要求 → 任务交付 → 实验与测试证据 → 对后续工作的影响”展开。输出重点是有依据的项目判断和行动建议，状态和完成率作为事实背景。

简单状态查询和单份会议整理按用户范围处理，不强制拉取整个项目。正式任务、审批、提醒和状态流转仍由业务页面与后端执行。

实现使用已有 `business_search/read/links` 及确定性核验工具，不增加查询接口、写入权限或项目编排器。项目关联能帮助发现对象，但不是任务依赖或实验验证关系的证明。

## 配置与方法

- `jsd-aird-api/src/main/resources/ai/expert-presets.json`：更新项目助理简介、能力、示例、职责、核验规则和交付结构；复用客户需求比较与实验比较技能。
- `jsd-aird-agent/enterprise-plugin/skills/project-diagnosis/SKILL.md`：规定读取、对齐验证覆盖、解释影响路径和交付建议的方法。

分析区分已验证、已有可比结果但未满足、未验证、条件不相容，以及关联待核实。分类是分析结果，不修改业务状态，不等同于正式质量放行。

需求变化须有真实前后依据。没有旧版时可分析当前要求的覆盖情况，但不能声称已完成变更比较；未批准的提议也不自动成为新基线。历史实验的有效性按当前条件逐项核对，不能全部沿用或一概作废。

影响分析须解释起点问题、来源、受影响对象、路径和建议。只有同项目关系时，只能提出有内容依据的候选关联；没有依赖、日期或排程依据时，不宣称必然阻塞、确定延期天数或关键路径。

## 业务验收场景

以下是待执行的行为验收标准，不是已通过的模型测试结果。使用获准的真实资料或明确隔离的样本，不向生产业务库补造事实。

| 场景 | 输入中的关键事实 | 应出现的分析 | 不应出现的判断 |
| --- | --- | --- | --- |
| 任务完成但要求未获验证 | 任务标为完成；客户要求耐磨与透明；已有耐磨结果，透明结果未记录 | 区分任务状态和目标证据，指出透明验证缺口；有明确依赖时解释对后续任务的影响，否则列潜在影响；建议核实或补齐结果 | 项目已达标；透明测试一定没做；无依赖证据却断言发样必然延误 |
| 客户要求变化 | 有前后原文与版本；新要求更改基材或方法；旧实验按旧条件完成 | 列真实差异，对相关结果逐项判断可沿用、需补验证或不可比；解释受影响任务及关联依据 | 所有旧结果失效；未经批准提议自动变成正式基线 |
| 仅有当前需求 | 当前需求和更新时间可读，旧版不可取得 | 分析当前验证覆盖，明确无法确认具体变更 | 因更新时间较新而编造客户新增或撤回了什么 |
| 任务和实验同属项目 | 任务与实验无明确交付或依赖对应；内容存在可能关联 | 候选关系说明内容依据并标待核实；给出核实动作 | 同项目即认定实验对应任务，或把先后时间当作因果和依赖 |
| 指标结果未满足 | 有适用规格、同条件实测和明确任务关联 | 使用确定性工具核对，指出目标缺口和后续影响，提出核查或验证建议 | 编造失败原因；把单个指标未满足直接归责某人或断言整个项目失败 |
| 历史依据与当前缺项 | 样品计数为零，但背景有历史配方及版本；当前实测缺失 | 读取背景与明确历史版本，区分已有依据、方案和本次未验证部分 | 零样品等于无配方；把历史值填成本次实测 |
| 权限或分页不完整 | 客户要求不可读，或实验相关分页未完成 | 说明受限或未覆盖范围，仅就已读证据给条件性分析 | 没有客户要求；已完成全项目影响核查 |
| 范围较小且无异常 | 用户仅问某任务当前状态；或已读范围内证据一致 | 简洁回答状态或说明未发现有证据的问题，按实际范围陈述 | 强行展开全项目报告，编造卡点以填满模板 |

真实模型验收时，应同时检查读取轨迹、来源与最终回答。回答提到了“影响分析”，不代表实际读取了要求和实验；能引用记录，也不代表推断关系正确。
