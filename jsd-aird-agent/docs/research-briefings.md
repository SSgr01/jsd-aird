# 内置研发简报

首次访问工作台安装三项原生自动化任务，默认开启，时间使用 `Asia/Shanghai`。工作日为周一至周五，首次计划时间始终在未来。

| 任务 | 默认时间 | 内容 |
|---|---|---|
| 项目晨报 | 工作日 09:00 | 在研项目、逾期及今日到期任务、阶段阻塞、资料缺口、优先行动 |
| 研发周报 | 周五 16:00 | 本周项目、阶段、任务和实验的活动，区分本周更新与当前状态 |
| 实验复盘 | 工作日 17:30 | 从上次成功位置至本次执行的实验；首次覆盖最近七天，包含独立实验 |

在工作台的原生“自动化任务”页面查看、编辑、暂停、恢复、立即执行或删除。每项使用独立、长期复用的原生会话，正文与业务入口保存在会话中。任务不自动写实验草稿、保存正式报告、生成文件或发送外部通知。用户修改、暂停与删除会被保留，刷新或升级不会覆盖。

## 后台运行与授权

网关必须作为服务持续运行，同时保持 Java API、Control、数据库与原生 Host 存储可用。开发环境使用现有 `scripts/dev-harness.ps1` 分别启动 api、control、gateway、web；生产环境由现有进程管理器看护网关。无需另启 cron 或企业调度器。执行时间、Inbox、消息交付与会话恢复继续由原生 Schedule 管理。

网关启动时按分页恢复授权有效的用户 Host，之后每分钟续签并检查进程状态。Host 退出后重建同一组织及用户的实例，复用相同 `DSH_HOME`、原生日志和任务目录。短期票据独立过期；换票失败不会永久延长身份。账号停用、组织变化、授权版本变化或撤销后台授权后，后续模型与工具准入失败。后台凭据不能兑换交互登录身份。

首次安装将可撤销授权、固定内置标识、预留会话及原生任务 ID 保存到现有 `harness_records` JSONB。不保存浏览器 Cookie，不新增数据库表或迁移。`/internal/v1/agent-identity/automation` 同时要求服务密钥、短期签名证明和实时 IAM 身份；签发的后台票据有效期五分钟。Control 与 Java 都限制研发读取范围，插件还核对原生任务 ID、真实投递回执、会话和 Turn；通用文件、命令和业务写入不可借用此授权。

首次创建任务前持久记录创建意图。响应丢失时先回读原生目录，以预留会话对账，不按标题匹配。若已有创建意图但目录中找不到任务，保留待对账状态，避免把已删除或结果未知的任务重新创建。需查明原生目录和安装记录后再处理，不能直接清除意图重试。

## 数据与完成语义

按需发现工具 `get_research_briefing_context` 返回服务端时间窗口、活动索引、固定版本 ref、分页和覆盖情况。Java 经项目及实验 facade 读取，各模块内部处理时间筛选与权限，不跨模块查询仓储。周报时间从本周一零点开始；更新时间只说明该记录在窗口内有活动，不能据此推断具体前后变化。

Control 固定本期各分区索引，分页期间索引改变则终止本期读取。模型继续使用 `business_read`、`business_links` 阅读完整正文与真实关联。实验按概览读取样品、配方、工艺、条件、结果等非空分区；局部样品和字段筛选不计为完整读取。分页按服务端实际返回的行区间计算覆盖，容许重叠，禁止缺页。

完整复盘和周报优先使用实验 `section=record`；超过原生读取预算时才按实际分区分页。实验引用同时固定版本 ID 和完整版本正文摘要，草稿在同一版本内编辑也会使本期引用失效。服务器从冻结索引补齐引用约束，模型省略摘要不能放宽校验。实验显示当前项目、阶段和任务归属；该归属明确与历史版本正文分开，仍须沿真实关联另读相关记录。

实验表格的样品列优先显示原始复合身份中的名称，身份未命名时读取同一样品的实际实验编号，仍缺失时显示“样品 N”。显示名称不替代复合身份；不同模板继续读取自身字段，不用一个模板的指标数量推断其他模板的内容。

长期会话保留前期全文和原生日志。已结束且已绑定内置任务的旧期只重新检查当前记录访问权限及实验版本归属，不拿旧草稿正文与现在的草稿强行比较；普通会话、活动轮次和本期证据仍执行原有严格校验。新一期不继承旧期的证据或覆盖记录，须重新完整读取。这样既能保留历史阅读，也不会把过期事实计作本期完成。

新周期在第一次模型请求前通过原生会话 `surfaceOp=replace` 关闭前期的模型上下文，保留完整原生日志、前期正文及当前消息。周期任务不是上一期的未完成工作，不能用通用编码检查点把旧工具错误和可变草稿带入新一期。该上下文操作记录完整来源序号，重启后可重放；同一期继续执行时不清空已读数据。本期内部的压缩及工具结果整理仍由原生机制管理。辅助模型请求经过同一授权和计量。原生 `turn/end` 是完成与失败对账依据，连接中断后重放尚未投影的终态，消息已投递不能替代业务成功。

原生执行历史是消息投递回执，不等于业务成功。`briefing-delivery` 独立保存原生投递、实际 Run 和业务终态。只有本期读取完整且 Run 成功，才推进实验复盘位置；停止、失败、未知结果及覆盖不足均保留原位置，晚结束的旧期也不能倒退位置。正式报告、草稿与文件仍遵循用户明确指令。

### 统计与样品呈现修复（2026-11-07）

实验概览原先统计原始样品数据单元格，分区分页却统计按字段、方法、条件和单位聚合的行，两者口径不一致。现在概览 `section_counts` 与分页 `total` 共用同一行投影，原始单元格数另存 `section_cell_counts`；例如两样品各三个指标为三行、六个单元格，不能称为六个指标。每个实验分别统计，不从一个模板推断其他模板。未记录指标也按完整方法、条件和单位分组，某方法有值不能掩盖另一方法未测。

供模型阅读的实验数据将样品、指标、方法、条件、单位与值放在同一表格行，继续保留数值零、未记录、未返回的区别；原始证据、固定版本及单元格来源没有被展示文本替代。简报工具从冻结索引生成 `index_summary`，返回各类型数量及总数，与模型当前读到哪一页无关，三项目、三阶段、九任务、八实验明确合计为二十三个业务对象。

定向检查覆盖两个标准模板的概览与分页一致性、多样品计数、不同方法和条件不合并、零值及未记录、完整记录读取、跨期索引总数及空索引。此改动消除输入中的歧义，不能据此声称模型的所有归纳均已正确；前面的失败正文和内容不通过项仍保留。
