# 可配置检索流水线与父块回取

问答接口和工作台按需检索经过同一个 Java 编排器。Node 运行唯一的 dsh 执行循环；Python 负责业务工具、权限及预算门禁、证据导航和操作回执，不维护另一套模型循环。RCS 继续由专业核查能力调用。

## 入口与代码

| 入口／组件 | 职责 |
| --- | --- |
| `SharedRetrievalService.retrieveFixed` | 保留问答接口所需的检索准备，模型执行统一进入 dsh |
| `AgentToolsController → SharedRetrievalService.documents/privateDocuments` | 按需检索工具，身份来自委托票据 |
| Java `ai/application/RetrievalPipeline` | 查询策略、召回编排、RRF、统一重排、排序分页、父块扩展 |
| Java `kb/application/KnowledgeService.recall` | 问答与当前知识库研究共用的原始 BM25、向量、元数据、兜底召回渠道 |
| Java `kb/application/ResearchKnowledgeService` | 授权／发布版本、历史原文词法召回、句柄回读、父块与精确跨度验证 |
| Java `ai/application/PrivateResearchSourceService` | 私有原文词法召回及同一账号、会话、版本的权威回读 |
| Java `shared/retrieval/RankFusion` | 共享 RRF；文件搜索兼容接口也使用该排序组件 |
| Python `evidence/navigation.py` | 任务内证据入口、排序快照、分页、重新授权与无进展检测 |

公共编排顺序：权限及版本范围 → 查询处理 → 各渠道原始召回 → 融合去重 → 重排 → 命中分页 → 父块回取 → 证据及上下文预算。

结构化记录和网页各自在可比较的召回组内排序；不把原始评分与 RRF 相加。模型按任务需要调用检索工具。普通读原文、邻近上下文、父块续读、表格读取不重新执行检索。

## 服务端策略

配置位于 `application.yml` 的 `app.ai.retrieval`，由 `RetrievalPolicy` 在启动时验证。没有管理页面、数据库配置或模型可编辑的流水线参数。

研究检索接受 256 字符内的完整标题和自然语言，不限制有效词项数量，不静默删词；词法匹配继续规范化空白、大小写并去重词项，`match_mode` 控制匹配方式，不解析布尔查询语法。空查询、无有效文字和超长查询返回字段规则。

- `profiles.qa`：沿用原查询理解开关和历史；BM25、向量、元数据及重排可独立关闭。
- `profiles.research`：默认关闭额外 LLM 改写；保留模型提交的查询。只有服务端显式开启时，控制层才预留一次辅助模型预算。缓存和排序快照回读不再计这次调用。
- RRF 默认 `k=60`；研究混合候选窗口先融合、重排，再按默认 12 条切页。全库发现的 `auto/any/all/phrase` 均先查询当前发布版本索引，不逐篇展开整个授权库。`any/all/phrase` 在有界索引候选中执行词语匹配，空候选不代表全文不存在；结果保留 `ranking_scope`、`fulltext_coverage=false` 及覆盖说明。指定文献及固定历史版本的原文词法读取继续检查完整指定范围。
- 重排未配置、失败、超时或返回不完整时保留可用候选；不按低语义评分清空精确命中。
- 指纹包含策略、配额及相关模型配置摘要。模型看不到内部 `ranking_snapshot`，不能用工具参数改写快照。

每次复用仍验证权限和来源权威性。自动库窗口另核对允许文献／发布版本的摘要；库窗口、身份、范围、版本或配置变化后重启该次搜索，保留原有合法证据及引用。恢复链继承轻量导航索引与策略指纹，不另存一套正文。

## 截止时间与部分结果

检索使用绝对截止时间，子任务只能缩短调用方剩余预算；排队时间也计入预算。默认值如下，均是服务端配置，模型不能修改。

| 层级 | 默认上限 | 配置 |
| --- | --- | --- |
| Java 内部检索工具请求 | 30 秒 | `app.ai.retrieval.tool-timeout-ms` |
| 知识库一次召回 | 20 秒 | `app.ai.retrieval.recall-timeout-ms` |
| 并行 BM25／向量渠道 | 各 10 秒 | `app.ai.retrieval.channel-timeout-ms` |
| Python 等待 Java 检索 | 35 秒 | 检索调用的传输上限 |

SQL 继续服从资源层更短的 READ 时限；Embedding、重排和查询改写继承同一剩余预算。异步任务传播截止时间及资源类型，工作线程独立释放自己的资源。等待超时会取消并中断实际任务；队列满时返回明确失败，不把工作转到请求线程无界执行。请求取消不会触发另一轮查询。

授权文献范围在排名前加入一次批量 BM25／向量 SQL，不逐篇循环查询。BM25 在词频聚合中携带段落长度，避免最终计分反复扫描整批候选；批量向量查询先物化输入向量，避免逐段重新解析同一向量文本。两项均保留原有公式、排名和固定版本过滤。

BM25 先按词索引读取匹配词，再与已授权的候选段落连接；文档频率用匹配段落窗口统计，避免反复聚合连接。候选段落仍受组织、权限、发布版本和 AI 授权约束。

超时后保留已完成渠道的候选，不再启动全文降级查询；即时索引故障仍可在剩余预算内使用原有全文降级。结果不完整时返回 `retrieval_status=PARTIAL` 及简短覆盖说明，不能把空候选解释为没有相关资料，也不应连续换关键词重试。Python 传输超时返回 `RETRIEVAL_TIMEOUT`，与正常空结果、权限拒绝分开。原始渠道 trace 保留在服务端供排查。

明确列出的只读请求遇到连接失败、网关暂时不可用或服务资源繁忙时，控制层最多重试一次，两次共用原传输总时限；参数、权限、版本、限流及截止时间错误不重试，写入不进入该重试路径。最终错误保留安全的 `error_code`、尝试次数及必要的字段修复信息，不转发内部异常正文，也不将失败写成查询未命中。业务目录查询只返回可用类型；项目资料 `MATERIAL` 要求 `filters.project_id`，不能当作按型号检索的物料库。

## 父块证据

最终 CHILD 命中确定后，仓储按 `parent_chunk_id` 一次批量读取，验证同组织、文档、文件版本、发布修订及 PARENT 角色。多个子块共用父块时只返回一次，`parent_links` 保存关联子证据 ID。

父块独立放在 `context_candidates`，角色为 `PARENT_CONTEXT`。它有自己的节点 ID、证据 ID、完整父块哈希、片段起止位置及片段哈希，不替换子块正文或 ID。

自动默认最多 3 个父块、各 2,000 个 Unicode 码点，总计不超过 6,000 及知识库上下文预算的三分之一。问答保留原 18,000 总预算和混合来源分配，包含头部开销；只给实际交给生成器的父块片段分配 K 别名。

问答压缩按检索排序分配预算，不再按页码或章节重组命中。每条命中保留独立来源标记和原有换行、表格行及段落边界，避免相邻记录串值或低排名长段挤掉更相关的方法段；预算末端截断仍明确标记。父块继续保持独立身份和完整片段，不在压缩阶段改写或截断父块正文。

片段优先覆盖能唯一定位的命中正文附近；定位不可靠则从父块开头读，并标注限制。片段逐字返回，不插省略号冒充权威正文。搜索、父块及相邻扩展均不增加全文覆盖。

`evidence_context` 新增 `relation=neighbors|parent`，默认不变。父块 `cursor` 为 Unicode 码点续读位置；`evidence_read` 仍通过现有 quote 句柄读取该证据片段。UI 区分父块片段、节点预览和片段内的精确引文。

缺失父块不丢弃有效子块；私有／历史节点缺少真实关系时返回不适用，不依据标题或当前索引猜测。权限拒绝继续返回权限错误。

## 证据原图与视觉模型

知识库中的 LaTeX 随原文证据读取；分子结构、反应路线和需要目视核对的公式通过 `evidence_image_read(evidence_id, view="auto")` 取图。证据必须已登记在当前任务账本，工具不接受模型提供的 URL、资产 ID 或任意文件路径。Java 每次重新校验权限、发布版本、正文哈希及锚点，并把解析图片限制在对应文档和文件版本内；当前请求指定的检索文献范围仍生效。

`auto` 优先返回该证据绑定的独立原图；没有独立图片时生成证据所在的 PDF 页。`view="page"` 可主动读取整页以核对公式、图注和上下文。单张图片最多 8 MiB，页面渲染读取的 PDF 最多 64 MiB，输出最长边最多 2200 像素。无法可靠定位时明确失败，不从其他文献或版本猜图。

正常问答每轮先读 1～3 张最相关的图，信息不足再定向补读，以控制费用和延迟。这是 Agent 的按需读取指引，不是数量硬限制；复用已读图，不默认同时读取每张原图和整页，用户要求逐图核对时按要求完成。

企业插件核验图片长度及 SHA-256 后，将文件写入当前原生会话的 `.business-data/`，移除模型文本中的 Base64，并返回 `business_file.path`。Agent 随后调用原生 `read_image(file_path=...)`，由原生工具生成真正的图片内容块；当前模型须明确支持图片输入，只有文件路径或 Markdown 链接不算已经看图。该流程不增加通读覆盖，不创建新的原文摘录，也不把视觉推断当作已验证的 SMILES 或立体构型。

## 书目、标签与回答规范

`document_metadata` 是可选的独立书目上下文，按授权文件版本和书目修订批量读取并去重，包含实际取得的作者、期刊、日期、摘要及原件入口。问答准备上下文及研究检索、目录、阅读和父块结果均可携带；书目不会成为正文 quote，也不改变正文哈希。摘要只能用于介绍与筛选。缓存、压缩和恢复保留书目修订，恢复后仍重新检查来源权限。

`DOCUMENT_METADATA` 发现题名、作者及标识符；`DOCUMENT_TAG` 读取对应发布快照的已有标签。两者分别记录原始召回，再进入现有 RRF 和重排；标签命中不代表科学结论已得到原文支持。渠道开关沿用 `metadata`，未建立第二套标签索引或发现系统。轻量发现结果在签发来源句柄前回填权威锚点，以保证分页与原文回读一致。

两个入口共用 `control/src/aird_agent/capabilities/answer_guidelines.txt`；Java 打包到 `agent-prompts/`，Harness 通过包资源读取。内容摘要纳入现有提示词版本与能力指纹。按实际意图介绍文献、提取适用信息或提出验证建议，不固化培训案例、必填材料字段或回答模板。

## 原文、候选结论与报告核查

模型沿用原生会话中的阅读结果。每步企业上下文只附加必要的业务状态，不重复追加增长的来源目录和普通阅读进度；用户明确要求全文覆盖时仍附加该任务的覆盖进度。检索返回命中原句及同节点上下文，不再额外附上整个节点正文；上下文不足时成组省略并返回明确阅读句柄。

每轮按固定版本证据 ID 与实际返回的字符范围记录交付回执，和来源登记、全文阅读覆盖分开。跨查询命中相同原句、分页重叠节点及摘录重复读取时，只返回句柄与摘录编号；尚未展示的跨度继续返回，不能仅因节点已登记而省略。新原句保留相邻条件，新表格行保留列头。预算先按去重结果计算，回执在成功结果提交事务内写入，避免并发读取重复交付。`document_read`、`private_document_read`、`evidence_read` 可用 `refresh=true` 重显正文，回读和缓存复用仍重新授权。模型可见目录仅保留标题、页码和节点范围，空间坐标及多边形留在权威账本和展示结果中。固定版本、样品条件及继续阅读句柄保留，完整权限、哈希与阅读回执留在服务端账本。

联合检索 `retrieve_context` 同样记录原文交付。其旧格式同时携带带标签上下文与完整候选；只将对应标签块中和候选完全一致的正文替换为引用句柄，保留查询状态、配方核对、歧义、图片及无法精确对应的片段，不直接删除整份上下文。

已知参数的独立检索、目录、原文、摘录及上下文读取可在同一步并列提交，建议每批最多 4 项。企业插件向原生调度器声明这些只读工具可并发；依赖前项 ID 或偏移的调用等待结果，写入保持独占屏障。各调用仍分别准入、校验权限并记录结果，不另建批处理执行循环。

本轮 Token 硬预算继续包含缓存用量。接近预算时根据已计费用量和最近请求大小提示优先完成原问题、说明资料缺口，硬限制不变。上下文压缩与执行循环继续由原生运行层负责。

原文引用接受证据编号及其哈希绑定的精确摘录编号；服务端只映射已登记来源中的真实摘录，未知编号或正文哈希变化仍拒绝。映射通过显示侧链传给原生 Markdown，不向模型重复注入原文链接目录。

每份工具结果将同一文献固定版本的标题、文档 ID、发布 ID、版本 ID 集中在 `document_sources` 中声明一次，片段通过该结果内的 `document_ref` 引用；片段保留证据 ID、页码、正文、条件、表格上下文及继续阅读句柄。引用声明不依赖跨调用缓存，恢复与压缩后仍可独立解释。完整来源及原文 URL 留在权威账本和 UI 侧链，业务记录入口不受该文献投影影响。Python 分页预算包含此目录，企业插件再按最终 JSON 模型投影检查读取字符上限，避免预算通过后追加长 URL。

最终答复的引用校验失败时，已知句柄的空格、括号、精确摘录别名、带重复 `E:` 前缀的并列引用先确定性规范化；并列引用中只要有一个未知句柄就不猜测转换，格式错误和未闭合引用不能绕过检查。原生流式显示采用同样的已知句柄映射。仍失败则返回具体错误句柄、行号、规范化后的字符位置、邻近原句及最多 12 条已读证据候选；候选只用于定位，不代表已确认支持该结论。修复默认最多 2 次模型请求、2 次定向补读，分别由 `JSD_AIRD_HARNESS_CITATION_REPAIR_MODEL_CALLS`（1–2）和 `JSD_AIRD_HARNESS_CITATION_REPAIR_TOOL_CALLS`（0–2）控制。计数与允许来源保存在 run 账本，重启或重复请求不能重置。工具执行层仅允许已有证据或已取得固定版本的读取，禁止扩展检索及业务写入；最后一次模型请求直接给出答复与资料缺口。现有文件交付仍可登记并接受原有哈希和回执检查。预算耗尽明确失败，不放宽引用合法性规则。

`matrix_record` 保存的是引用绑定的候选解释，压缩恢复仍保留 `AI_CANDIDATE_NOT_FACT_VERIFIED`，不能把候选措辞当成原文。表格读取和核查使用发布版本内已确认的表头关系；报告中的列条件与数据行一起送审，不跨对象、统计口径或试验借用数值。原文单位异常时保留原标注，不猜测修正。

报告作者的缺失引用、与原文矛盾和未回答问题，属于内容修改意见。核查器自己的遗漏、错句柄、跳过事实或理由编造测量值，属于核查输出故障，只在核查器内修复一次，保留有效批次。仍失败则本轮停止核查并保留草稿；改标题、正文或矩阵不能重置该预算，后续用户请求可开启新一轮。权限、额度及未知写入结果继续执行原有约束，不能因此跳过核查保存。

完全相同的报告复用已记录检查；局部改稿按断言、原文身份及全文、表格条件和用户问题的摘要复用未变化的事实判定，仍重新检查完整新稿的问题覆盖。重复写入相同矩阵不增加修订；真正的矩阵变化仍使旧整稿核查失效。核查故障单独记录，页面不会据此声称报告数据错误或缺少原文支持。

报告保存的来源授权及原文校验按同一请求内的文件版本批量复用读取，逐条核对来源身份、正文哈希和摘录，不跨请求缓存权限。超时或结果未知继续先对账，不能通过重放保存掩盖未知结果。

## 本地质量评测

复用入口为仓库根目录的 `scripts/local/evaluate_knowledge_quality.py`。通过 `--cases` 提供本地案例 JSON，`--output` 指向忽略目录；`--cross-entrypoints` 运行清单中标明的双入口题，`--retrieval-only` 单独测检索。清单字段与凭据环境变量见该脚本 `--help`；答案、原文、运行事件及截图不提交。

参考答案只在本地判分，不能发送给模型。Run 结果未知时，同一输出目录只通过 GET 补收原任务，不重复创建或恢复执行。服务端事件用于研究首字及总耗时，回放采集时间单独记录；缺少账单或价格时费用为未知。

必要事实按替代证据组计数；文档排名按文件版本去重。当前自动 Recall@20 对 CHILD 排名计分，父块及各页书目、trace 单独保存以便核对，不能将其包装成已测过完整上下文召回。Precision@10 的自动值使用文档相关性判断，段落是否准确支持科学结论仍须对照原件。标签、书目、正文分别报告样本数与失败，渠道命中不能代替融合后排名或完整回答验收。
