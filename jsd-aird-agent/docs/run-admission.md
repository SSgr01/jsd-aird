# 运行入场与恢复

控制服务的 `RunAdmission` 只负责分配名额和投递请求，模型及工具循环由 DSH 执行。PostgreSQL 的 `harness_admission` 保存等待记录、租约、投递回执和管理员诊断，原生 Inbox 保留尚未领取的输入。

默认每用户同时执行 2 个任务；全局上限沿用现有 `MAX_RUNNING_RUNS`，组织上限未配置时等于全局上限。`MAX_RUNNING_RUNS_PER_USER` 和 `MAX_RUNNING_RUNS_PER_ORGANIZATION` 使用 `JSD_AIRD_HARNESS_` 前缀配置。组织间及组织内用户间按持久化最近分配顺序轮流服务，同一用户按提交先后运行。

请求先持久化入队，取得租约后才投递 API 请求或放行原生 `agent/pre-turn`。工具检查和激活复用同一代次。等待不计入运行时间；原生运行注册后开始计时。发送后，请求显示在原生用户气泡中；排队时，原生回答等待提示显示“当前任务较多，正在排队”，使用输入框原有停止按钮取消。取得名额后自动继续。页面不提供额外排队面板或管理员诊断，内部诊断仅保留在受权限保护的控制接口中。

宿主默认每 10 秒续租，租约 60 秒到期；两项设置分别为 `ADMISSION_HEARTBEAT_SECONDS`、`ADMISSION_LEASE_SECONDS`，到期时间必须至少为续租间隔的三倍。控制服务在投递期间负责续租。投递响应丢失后复用原生请求 ID；暂时故障自动退避，连续 6 次未成功或明确不可恢复的错误会结束自动投递，提供重试入口。

控制服务启动先接管旧 `RUNNING/QUEUED` 记录，再分配新名额。到期或取消的租约在确认宿主停止前仍占名额，状态不可确定时不会假定任务已经结束。确认停止后递增代次，拒绝旧回执和旧工具调用；保留请求并恢复等待。已经开始但结果未知的业务调用记为 `UNKNOWN`，沿用既有业务对账流程，禁止自动重复副作用。

取消先保存取消状态并阻止继续执行，再通知宿主；停止响应丢失时由对账确认。原生等待取消只移除匹配本次输入签名的待处理批次。永久删除会话在原生停止并提交删除后释放对应租约。

恢复入口用 `wakePending()` 唤醒原生 Inbox 中保留的输入，不插入替代消息。只有确认原请求既不在队列也不在运行时才投递持久化恢复请求。宿主明确确认原生日志不存在时，释放名额并提示新建对话；连接超时不会被当作日志丢失。

失联宿主可能延迟释放名额，这是避免旧实例与恢复实例同时执行的限制。租约防止过期实例发起新的受控调用，不能撤销已经发出的模型请求或外部副作用。普通失败仅在没有未知副作用且原生宿主已停止时允许安全重试。

化学卡片的“RDKit 校验通过”只表示 SMILES 可解析、原子价态有效。同组 canonical SMILES 相同会提示重复。原图核对依赖部署端可追溯记录，当前记录为空；本次不处理论文结构纠错。反应结构绘制不表示反应配平或机理已验证。
