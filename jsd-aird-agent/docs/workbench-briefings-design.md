# 首页「研判与行动」设计

日期：2026-11-11。状态：首页与原生会话入口已实现，本地开发服务已加载；未提交或部署生产。

## 首页内容

保留选定的「研判与行动」版式：晨报为主，周报与实验复盘为辅；下方保留项目、实验和待处理事项入口。

- 本期重点：一句研判及简短摘要，展示实际生成时间与报告范围。
- 建议行动：最多三项，每项关联真实项目、任务或实验，点击进入现有业务页面。
- 简报入口：分别标明「查看晨报」「查看周报」「查看复盘」，界面无需说明会话实现。

摘要与行动由查询层从同一期成功结果的 Markdown 确定性提取，优先读取「本期重点」「建议行动」，不重新调用模型。旧期兼容已有段落；行动链接只从整期重新授权后的业务证据身份生成。后续实际生成沿用现有模型调用，在正文开头组织这两个章节。刷新首页只查询。

## 阅读与追问

点击入口进入该类简报现有的长期原生 AI 会话，优先定位到所选期次对应的结果消息或轮次。历史结果、完整 Markdown 正文、业务引用及继续追问均沿用原会话。不得仅打开会话末尾而让用户误认其为选定期次；消息定位能力需在实施时验证，无法精确定位时显示期次提示并明确降级。

取消此前新增的完整阅读页、阅读抽屉、正文目录、独立简报历史页和自建追问输入框。首页不把简报转存为研究报告实体，不创建新的会话或报告正文副本。

## 状态与权限

沿用现有运行与业务终态语义。生成中或失败时如展示上期，必须注明日期和本期状态；无新增内容时如实展示。访问摘要、原会话及关联记录均须遵循现有权限，不得通过首页暴露已失去权限的数据。进入原会话成功并显示对应内容后，才可按实际能力处理未读状态。

## 原型边界

原型仅演示首页内容与原会话导航关系，业务内容均为示例。点击会话入口显示跳转目标提示，不连接真实会话，不发送消息、不调用模型、不写业务数据。旧稿中的独立阅读流程作废。

## 已实现的链路

- Web 首页通过 `GET /api/v1/agents/briefings` 获取个人结果；Java 沿用委托身份代理，响应禁止 HTTP 缓存。
- Control 按组织、用户、内置类型、原生任务与会话选择最新运行及最近成功期。失败、运行中、读取不完整和无新增实验分别展示，不能将部分输出作为成功结论。
- 返回摘要前重新检查整期来源权限。前端查询缓存沿用用户、组织及授权版本隔离；重新检查失败时隐藏旧摘要与链接。
- 入口使用 `/agent/?briefing=<kind>&run=<id>`。服务端重新核对所属任务、会话、轮次和来源权限，前端仅调用原生 `uiWorkspace.openSession`。
- 原生 Chat 未提供可用的公开跳转轮次接口，目前显示所选日期和轮次提示，由用户使用原生轮次导航查看。没有改动原生实现或增加另一套正文阅读器。
- 报告完成时间固定保存，首页不使用会随权限检查而变化的更新时间。

## 本地数据与检查

按用户要求构造两期晨报、一期周报、一期复盘，每篇约 1,100 字；正文、表格和可点击的业务引用已经写入开发组织管理员 `org_owner` 的三个原生长期会话。界面不添加模拟、验证或验收标签。构造数据来源标识仅保存在运行元数据中，未改动项目和实验正文。

该开发账号的三项原生计划已暂停，避免自动调用模型；四期运行的模型调用及工具调用计数均为 0。准备脚本、可恢复的原生日志备份、接口检查结果和桌面／390px 截图保存在忽略目录 `.runtime/homepage-briefings/`，其中账号文件含短期登录凭据，不提交。

已通过：前端定向测试 7 项、Python 23 项、原生入口及计划测试 8 项、相关 Java 单元测试、前端生产构建与包体积门禁，以及修改文件的 ESLint/Ruff 检查。9 项已有 PostgreSQL 隔离集成测试因未设置测试库地址跳过。本地实际服务另行检查了三类卡片、四期会话绑定、最新失败回退、跨用户拒绝与禁止 HTTP 缓存；浏览器检查了三个入口的长文及引用显示、原生轮次导航和桌面／窄屏布局。
