# 本地历史实验提取与训练候选

当前阶段在本地验证，不调用系统DSH、上传、导入、审核或训练接口。保留既有两种系统绑定任务的XLSX交付协议。历史资料有价值但不适合固定模板时，交付可追溯的实验数据；无实验事实的文件明确归档。

## 来源与执行

使用当前已有openpyxl。读取XLSX/DOCX工作副本；XLS/DOC先通过项目的`TemplateFileNormalizationService`严格规范化，禁止用预览降级或只改扩展名。记录原件和工作副本各自的SHA256。规范化只解决文件格式，语义映射仍需模型逐份理解。

历史提取不要求空白标准模板；ROOT只需包含本次原件/工作副本和独立输出目录。不要让输出覆盖原始资料。仅当需要生成标准Excel时才准备`标准模板/`并使用原来的模板工作区约定。

```text
python -X utf8 scripts/history_data.py inspect --root ROOT --source 原始实验/测试实验/文件.docx
python -X utf8 scripts/history_data.py execute --root ROOT --plan PLAN.json
python -X utf8 scripts/history_data.py batch --root ROOT --manifest BATCH.json --output 批次结果.json
```

inspect返回紧凑概览和完整来源JSON的位置；定向读取相关表、区块及图片，不把全目录正文装进上下文。图片按Office部件列出并计算指纹；不得仅因正文只有标题就认定实验内容为空。

本地单份64MiB、ZIP展开256MiB、单部件128MiB、非空源格200000的限制用于明确拒绝，不静默截断。这些限制不改变服务器原有8MiB单份和沙箱传输限制。

所有事实字段必须引用来源。工作区内的路径受边界及指纹检查；原件、模板不改写，已有不同结果不覆盖。每个结果目录包含`history.json`、`mapping.json`、`verification.json`、`review.csv`和原始图片副本。

## 映射计划

`source`相对ROOT，`source_sha256`绑定实际读取的工作副本。`original`可提供原件副本路径和指纹。计划中用稳定内部key关联实验区块、组别；内部key不是补造客户实验编号。编号、日期按原文提取；人员可按SKILL.md中本客户已确认口径从相关单元格、标题和文件名查找，推定时另记依据。

```json
{
  "source": "原始实验/测试实验/文件.xlsx",
  "source_sha256": "实际工作副本SHA256",
  "original": {"path": "原始资料/文件.xls", "sha256": "实际原件SHA256"},
  "records": [{
    "key": "sheet1-study",
    "experimentType": "TEST",
    "metadata": {"date": "Sheet1!D2"},
    "groups": [{"key": "a", "identity": "Sheet1!C4", "identityType": "EXPERIMENT"}],
    "formulaItems": [{
      "group": "a", "material": "Sheet1!B5",
      "amount": {"ref": "Sheet1!C5", "parse": "number"},
      "stageKey": "addition-1", "compositionBasis": "UNSPECIFIED"
    }],
    "processSteps": [{"group": "a", "order": 1, "operation": "Sheet1!C10"}],
    "testResults": [{
      "group": "a", "item": "Sheet1!B20", "semanticKey": "water_contact_angle",
      "value": {"ref": "Sheet1!C20", "parse": "interval", "unit": "°", "unitRef": "Sheet1!B20"},
      "conditions": {"substrate": "Sheet1!C8"}
    }]
  }],
  "structural": [{"ref": "Sheet1!A1", "reason": "实验题目标签"}],
  "unplaced": [],
  "templateAssessment": {"decision": "NOT_SUITABLE", "reason": "多时间点及基材条件不能完整放入现有模板"}
}
```

坐标使用`工作表!A1`、`table-N!A1`、`paragraph!1`；可以跨表引用元数据，但必须确认它确实属于当前实验。单元格引用不能指向不存在的空白坐标；源未记录的物料不新增，字段原始缺失不伪造；本客户已列物料的空白/横线/斜杠用量可依已确认约定在有效层解释为未投料0，原始提取与原文仍保留。Word真实网格和嵌套表地址使用既有执行器的视图，跨列合并只算一个物理来源。

配方逐项提供物料和用量来源，支持每组不同物料、分阶段重复投料。`stageKey`是阶段的内部关联键，原文阶段说明应放入工艺事实；不能用键名暗示原文没有的工艺。`totals`可声明`group`和源合计`value`，仅在全部用量已数值化、计量单位一致时重算比较。冲突进入报告，不修改实际用量。

`recordRole`默认为`EXPERIMENT`；对比汇总页用`SUMMARY`，保留事实但不作为新增独立实验进入候选训练。汇总与原实验的关联需核对，不能因编号相同就合并。日期按每条记录及各组的真实日期判定；无日期的附页可以提取并单独列待确认，不能借同文件其他页或目录年份填日期。

章节结论等文件级文字放入计划的`documentFacts`：每项给`role=SOURCE_NOTE`、`reason`和来源`field`，与单独实验分开。有物料名但无用量的行用`role=UNQUANTIFIED_RECIPE_LABEL`保留；不补零，含这种缺项的文件不得直接用于配方候选训练。

空白模板自动生成的零/错误公式可单独用`role=TEMPLATE_CALCULATION`保留，不能只凭值为0或错误就认定无意义。声明`field`及`proof={"identityRef":"工作表!X4","inputRange":"X6:X19","observationRange":"X23:X39"}`后，脚本读取实际来源验证：目标为有缓存的零/错误公式、同列身份为空、投料范围无真实用量、观测范围无真实结果。输入范围只允许空白或已映射的物料名称。真实零值常量、已有编号、任何用量/观测均拒绝这种分类。诊断仍保留原公式、缓存及出处，不生成实验观测，也不删掉错误值。

`processSteps.parameters`、`testResults.conditions`都是“字段名→来源字段”的映射。多段LED/172nm/汞灯工艺按步骤保留；多温度、多基材、多时间点分别记录观测。物料名或编号相似不等于同一物料；材料主数据匹配另经核对，脚本不赋造materialId。

## 原值与类型

每个字段保留rawValue、单位、规范化值和sourceRefs；解释状态为PROPOSED，不代表人工确认。

- 原始来源解析与有效解释分开：已确认默认规则见SKILL.md；原始提取仍保留缺失/原记号与诊断，不以默认值覆盖证据。缺省`parse=text`，保留来源文字；`parse=number`只接受有限数字和无歧义数字文本，拒绝`0..1`、布尔值及带未知单位的内容。
- `pattern`是显式且唯一命中的提取正则，配合`group`取值；保留完整原文。不能凭正则将不同检测项认作同义项。
- `parse=percent_points`仅在原文有百分号或Excel格式证明百分比时，将比例转换为百分点数值。0.2配百分比格式对应20；普通0.2不能猜成20%。
- `parse=interval`保存上下界；`parse=bound`保存比较符号和限值；`parse=qualitative`保留OK/NG等定性值。不取中点，不把通过/失败边界当单一性能值。
- `unit`须由原文、numberFormat或`unitRef`证明；不自动补g、μm、小时等单位。未知单位保持空白。
- `/`与缺失、零值有不同类型。公式缺缓存或Excel错误值保留为INVALID并列出问题，不能假装重算成功。

图片字段的`ref`使用`{"image":"word/media/image1.jpeg","sha256":"实际图片指纹","bbox":[0,0,1,1],"text":"该区域可辨认的原文"}`。bbox为归一化区域。它是模型转录，必须对照原图核对；脚本只验证图片身份、区域和解释类型。不要猜读模糊数字。原图可以按`source-images/`路径查看。

照片需检查表头、配方、条件、每条结果及结果下方的损伤备注，不因同图已有一处转录就声称整图已提取。长度×数量分别保存原长度单位与数量，不把cm悄悄改成mm。模糊次数用明确的待辨认转录标记保留，数值解析为INVALID/空；旧读法和可能读法只放问题说明，不填入确定值。

`wear_observation_cycles`表达特定试验次数下的OK/NG观测，`reported_damage_mark_length`表达该次试验的损伤长度备注；保留同组、次数与评价关联。候选脚本拒绝将这两类观测直接作为耐磨寿命回归目标。测试次数、失效终点及上下限需要不同任务口径，不能将同组两个试验点当两个独立寿命样本。

## 状态、完整性和批量

- EXTRACTED：声明的来源已处理、无未解释来源或类型问题，仍是待人工核对的数据草稿。
- PARTIAL：存在未落位数据、未读图片、图片转录或类型/合计问题；原值及出处均保留。
- ARCHIVE_ONLY：`records=[]`且有明确`archiveReason`；不声称生成了实验。
- BLOCKED：来源、指纹、映射声明或执行失败；其余批次项继续。

未声明的非空来源自动进入unplaced，不丢失。纯数字观测不能声明为结构标签。报告分开列mapped、structural及unplaced数量，不把“都有处置”当成“全部已结构化”。空白表式中的标签可以明确标记结构，不能把真实检测数据当标签排除。

批次manifest使用`{"items":[{"plan":"相对路径/plan.json","output":"结构化结果/结果目录"}]}`。每份计划独立，不按相似版式套用其他原件的语义。生成的结果是同一现有实验事实结构的本地草稿，不直接导入系统。

## 按任务生成候选表

在扩大批量后先汇总核对缺项，可运行：

```text
python -X utf8 scripts/history_review.py --root ROOT --input 结构化结果/结果目录/history.json --output 核对清单/本批次 --requirements REQUIREMENTS.json
```

`--input`可重复。requirements可省略，或用准确语义键指定任务所需条件，例如`{"water_contact_angle":["substrate","bakeTemperature","bakeTime"]}`。先校验数据及原件指纹，再输出review.json/review.csv。每行保留来源和原值，确认值、核对人初始为空；已有清单不覆盖，避免丢失人工填写内容。

任务只适用于部分文件时，使用`{"rules":[{"sourcePath":"原始实验/测试实验/文件.xlsx","semanticKey":"water_contact_angle","requiredConditions":["substrate","bakeTemperature","bakeTime"]}]}`限定来源；不要把一个烘烤接触角任务套给所有接触角实验。规则不满足只表示当前任务条件不足，不表示原实验记录错误。未定义口径的记号笔数值应先确认是评分、等级还是其他测量，不直接要求补物理单位。

清单区分逐份核对、未落位适配、图片核对、来源冲突、物料匹配、单位/计量基准和任务条件。结构化字段为空不证明原文没有：提取方先检查原文标题、脚注和Excel格式，有记录就补映射，没有记录时先应用SKILL.md的已确认约定；缺日期只留空说明、明确对应模板的缺单位按模板默认，其他确实需补的再向作者询问。pH、折光率等明确无量纲项不要求补单位。不得凭合计反推改写实测量、合并重复投料、猜测材料身份或把填写清单当作系统审核。

本地历史整理已明确采用完整明细合计口径。原始提取仍保留来源合计和冲突；在独立有效数据层/整理副本中，计入同组同层级全部已明确投料，排除日期及说明，数字文本明确转换，漏项和手填算术错误直接纠正并记录旧值/旧公式、依据坐标和新值。重算依赖的计算项及其公式缓存，计算固含不得改标为实测固含。已有明细的母配方与最终混合比例分层，除溶剂扣除记为质量平衡而非负物料；未知用量、单位不兼容或组别不清时不强行求完整合计。已纠正的算术不再作为客户待答问题；经证明属于空模板的0/错误缓存不打扰客户，真实零值保留。来源仍只读，原始证据不得用整理值覆盖。

对某作者记法的真实反馈，记录原话、来源指纹、具体单元格及适用范围，与原值分开保存；只更新该范围的有效解释，重算依赖值。若用户明确授权某作者、某字段的记法可统一处理，在该已授权范围应用；不得扩为“所有a/b用量都取前数”，也不得仅因同人就外推到未经确认的其他字段。字段澄清不等于整份人工确认。

跨人员/时期抽查同时交付选样覆盖及限制、文件指纹、表/单元格/图片位置、原文、误转风险、处理办法和真实待补问题。优先查看多值同格、单位及测量方法混用、目标/实测混用、等级好坏方向、同名跨日记录、原料批次/生产/实验日期、工具规格/干膜厚以及投料/出料质量平衡。可明确判断的由提取方处理；目录归属和文件名年份只供选样，不冒充署名/日期。原件缺失、0字节及规范化失败分别列出，不按转换成功计数。

输出的`questions.json`按文件与问题类型合并重复提问，保留全部组别、来源及原清单行号。已由客户统一确认的单位不再提问；其他真实计量歧义按文件合并为具体问题；逐份确认仍按文件分别保留。物料主数据匹配、未落位适配和任务条件准备放内部处理，客户仅确认原文歧义或缺项。合并答案必须注明适用工作表/组别，不意味着自动保存共享映射规则或代替每份确认。

修复映射后可传`--previous-questions 旧清单/questions.json`保留同一来源路径、指纹和问题类型的编号，新增问题追加编号；来源指纹变化时不复用旧编号。编号延续不代表旧答复自动适用于新范围，重新生成的确认内容仍为空，人工反馈须另行对照处理。

本地反馈闭环：客户填写问题编号、确认内容/适用范围及核对人；提取方核对反馈与原文/指纹，将人工补充证据与原始事实分别保留，再修正对应映射、重提取并核验。未收到真实反馈时明确保持等待，不能代填确认或继续依赖这些结论的训练、导入和审核。

## 客户能够直接填写的核对资料

机器生成的review.json/questions.json是内部追溯，不直接作为客户工作表的单元格内容。客户表仅保留短说明、真实待补问题及逐份确认：每行列出文件/原文位置、具体原文、一个可理解的问题、答复和姓名；例如“原格写110..69，实际投料多少克？”，不显示错误码、sourceGroupKey、哈希或JSON对象。内部匹配、模板适配和机器诊断另放内部明细。可后补的检测条件与必须先澄清的原文歧义区分，已确认的单位和确定算术不再让客户重复回答。

逐份确认链接到可读的整理资料，按实验/样品展示配方、工艺、检测条件、原记录及整理值，标明原文位置；未知值仍是未知，来源汇总及无日期附页不能冒充新实验。配方原单位未写、用户已明确统一实际投料单位时，在有效层补充该单位和用户约定的证据，原rawUnit及sourceRefs不变。仅说明单位不等于确认物料纯度、溶液浓度或添加百分比的分母；原文明确的%、‰、ppm及配比不强改成质量数值。按质量公式得到的设计质量可继承已确认的质量单位，但须保留“计算/设计”性质。

客户表和内部追溯通过独立的行号/来源对应关系关联；改版前保存已填写内容，具体问题已有答复时迁移，不将客户填表状态当作系统审批。批次约定只应用在明确的客户资料范围，不能写成所有客户的默认单位。

## 物料原名与来源汇总整理

```text
python -X utf8 scripts/history_materials.py --root ROOT --input 结构化结果/结果目录/history.json --output 内部整理/物料原名
```

输出原名索引、出现位置、格式候选和来源汇总关联候选；先验证提取指纹、工作副本及原件。索引逐次保留投料阶段和用量，不合并同名重复投料。比对键只供比较，原名不改；浓度、溶剂和组成说明不剥离。纯编码的连字符/大小写差异也仅提出候选，不当作已确认别名。

来源汇总只在同一份数据内按原编号列候选实验，不能因编号相同就继承日期或计为独立样本。真实系统物料主数据未提供时，物料ID保持空白，不拿历史原名或比对键冒充ID；当前系统Material.id为UUID，与code/name分别保存。

```text
python -X utf8 scripts/history_training.py --root ROOT --task TASK.json --input 结构化结果/结果目录/history.json --output 训练候选/任务名
```

task明确`targetSemanticKey`、`targetUnit`、`requiredConditions`、`conditionEquals`，必要时指定`testMethod`和`testStage`。`conditionUnits`可限定条件单位，`dimensionlessConditions`须明确列出无量纲数值条件；其他数值条件缺单位或同一输入特征混用单位时排除，不自动换算。涉及配方时还要给出任务内明确的`materialVocabulary`、`compositionBasis`、`formulaUnit`。脚本不从相似名称匹配物料，不推断计量基准。

候选筛选保留来源及`splitGroupKey`，排除单位/条件不一致、目标非标量、合计冲突及未核对图片转录。重复投料保留阶段，不自动相加；`/`只有显式`notUsedAsZero=true`才可在候选特征中表达不用量0，原始事实保持NOT_USED。缺失物料不能自动补0。

输出candidates.csv、candidates.json（含排除原因）、task.json，始终`approval=NOT_GRANTED`。这不是训练动作或人工审批。正式训练仅接入现有已完成实验事实和有权限的数据集；复用系统的同实验/相同输入分组验证，不直接训练本地提取草稿。理论值、设计值、计算值与实测值必须分开选择。

候选行数与独立实验数分别报告。几十个时间点或条件观测可能只来自一个实验，不能按行随机拆分来声称模型有效。`includeFormulas=false`仅适用于明确不使用配方特征的任务，不能把仅有基材/处理条件的候选表描述成配方性能预测数据；仍需人工核对测量方法、独立样本及验证口径。

## 标准模板输出

明确原标签的本地测试投影另支持`ph`、`resin_viscosity_verbatim`及`particle_size_verbatim`。pH保持无量纲；原文保留字段只接收TEXT/QUALITATIVE，保留8S/2#、3040cps或“已胶化/无法测量”等完整记法，不猜方法、单位或把状态造为数值。它们仍受来源标签、条件、多项观测及未落位检查约束。

需要从统一数据生成标准Excel时，使用本地`history_template.py`：

```text
python -X utf8 scripts/history_template.py --root ROOT --history 结构化结果/结果目录/history.json
python -X utf8 scripts/history_template.py --root ROOT --manifest PROJECTION-BATCH.json --output 模板适用性结果.json
```

它核对提取数据与映射指纹，重新读取实际工作副本并重编译原映射，逐项比较当前事实。使用`template_ops.py`从空模板写入及扩容，保存后重开检查数据、合计缓存、标签、下拉及打印范围。不能从history.json抄字面值声称已核对原件。

批量清单使用`{"items":[{"history":"结构化结果/结果目录/history.json"}]}`，可逐项指定`output`。单份BLOCKED或SKIPPED不会阻断其他项；每份保留自己的来源核验与适用性说明。

默认仅在提取判断POSSIBLE、无未落位/类型/合计问题、单位和条件能完整对应时输出PROJECTED草稿及`.projection.json`来源清单。显式使用`--allow-partial`（API `allow_partial=True`）可输出PARTIAL草稿：已支持的事实落位，未落位事实继续保留于已验证的history及外部清单，不能称为整份完成。该选项不放宽类型、单位、条件、来源或合计校验；无实际配方、工艺或检测事实不生成空表，构建失败也不输出半张表。每组同一测试项的多项观测、无法表达的条件及未知项目不硬塞模板，不把SUMMARY当新实验。只有样品身份的测试不补造实验编号或0g配方。

当前自动语义表仅覆盖明确标签及单位的接触角、摩擦系数、部分外观/固含/折光率等字段；任意陌生项目不会通过子串相似自动选行。部分工艺参数可在单步骤且口径明确时对应；合成温度需明确油温或料温，保留原文角色。未覆盖内容继续保留在统一数据里，不宣称支持所有历史版式。本客户已授权：原单位缺失且指标对应明确时可在有效层采用模板默认单位并注明依据；原单位明确、模板有多个候选单位或指标对应不清时不得覆盖或猜选。

仍需直接从源坐标进行已确认模板转换时，可继续用`execute_plan.py`。固定物料行可显式`recipe.amount_transform="numeric_text"`；物料逐组排列可使用与groups等长的`recipe.entries`，每组是`{"name":"源物料格","amount":"源用量格"}`列表。

entries按物料原文建立稀疏矩阵，不存在的物料保持空白，不引用别组或不存在的空格。单组内同名物料多次投料需要阶段信息，固定模板不能表达时保留历史数据，不自动合并。同一来样参与多个实验可以重复sample_groups，实验groups仍须明确区分。

验收同时检查：分组与条件、来源、原值类型、未落位数、图像转录限制、合计冲突、任务候选排除原因。不能用一次脚本运行成功替代语义核对。
