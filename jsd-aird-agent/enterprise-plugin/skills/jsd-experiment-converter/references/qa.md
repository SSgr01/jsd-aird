# 校验与停止条件

本地历史提取另按[history-data.md](history-data.md)验收：区分提取完整度与训练资格，检查每项观测的组别、条件、原值类型、单位和来源。图片转录必须保留原图；未知单位不补猜；未落位数单独报告。历史数据脚本回归为`python -m unittest test_history_data test_history_template`，原有模板回归继续执行。

服务器文件夹模式的检查针对当前文件；校验状态表示机器执行情况，不维护人工核对状态。完成后按 [server-folder.md](server-folder.md) 用受控文件出口保存，客户在文件夹自行逐份核对，不能说已人工确认或已导入。

## 每个文件一次验收

1. 源表清单全部有处置：转换、空表或有原因的跳过；有意义的表不能因只跑了前几张就遗漏。每个非空源单元格都有 mapped / structural / unplaced 记录。structural 只能是字段标签/布局，不可用来豁免真实测量值。
2. 源组数、物料名、用量、每个条件/板号/原报告均值与输出逐格核对；确认同名组的不同表没有串值。计划执行器会重开文件核对写入结果；**语义是否选对行仍须人工读源/目标标签**。
3. 所有模板静态标签保留。配方扩容后的合计区间、验证、纵向块合并、冻结和打印范围正确；组列扩容后的合计及固化方式下拉覆盖新增列。执行器同时检查内联下拉值属于选项，如 `UV光固化`，不能写成 `UV`；外部引用下拉需要另作适配。每表使用从未填写的模板底稿。
4. 合计与独立算术、源合计（若有）一致。空配方返回空白，稀疏配方的空白和 `/` 贡献0。缓存只能写入真实公式单元格。自带执行器只支持其生成的数字 SUM 合计，不能冒充通用公式重算。
5. 未落位值附原位置、原值、原因。备注只含源备注；源无备注则为空。输出无技术日志/辅助工作表。

结构检查命令（从 skill 目录运行）：

```text
python -X utf8 scripts/workbook_audit.py --kind test --template TEMPLATE.xlsx --output OUTPUT.xlsx --expected-sheets 2 --min-groups 6 --min-recipe-lines 9
```

min 参数按实际文件设定。该脚本使用当前模板版本的坐标，只是补充检查，不能替代源数据和语义核对；新模板变动需同步适配。合计缓存缺失会警告，不算自动通过数据校验。可用既有 Excel/Univer 预览检查版式；无渲染器时注明未做图像检查，不为预览反复安装工具。

## 失败后的动作

报错应缩小到具体文件/表/单元格。修正后只重试一次，同错仍在就保存计划和失败原因，继续独立文件。不要通过删除校验、填0、合并物料或重建模板绕过失败。每个成功文件持久化状态后再进入下一个。

## 回归

`python -X utf8 scripts/test_workflow.py` 使用随包空模板在临时目录运行：合成双表数据与合计、两轴扩容、空白底稿隔离、缺失映射与过期指纹拒绝、嵌套docx表提取。

`python -X utf8 scripts/test_client_template.py --root ROOT` 另跑8项合成夹具回归：独立编号、客户追加行、两轴迁移、默认严格合计拦截与显式审阅状态。只需ROOT有标准模板，测试产物位于临时目录。
