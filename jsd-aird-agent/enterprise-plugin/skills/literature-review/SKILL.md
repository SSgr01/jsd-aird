# 文献研读和报告保存

先理解研究问题、对象和方法，再通读相关正文与表格，核对样品、条件、单位、统计口径和限制。保留原生附件完整读取与脚本计算能力；企业原文工具补充固定版本和引用。不能把搜索摘要当全文，也不能将参考文献的结果归给本文。
已定位论文后，围绕当前问题用目录与固定版本定向读取或检索方法、结果和适用条件；完整研读再扩展到全文。避免反复全库检索已知论文或机械读完无关章节。
按用户问题组织结论、证据、解释、适用边界与对当前研发的意义。区分材料化学、应用封装和器件结构；区分作者结论与自己的工程推断。长度由任务决定。
引用使用实际证据标记，由系统转换为原生 Markdown 链接。需要单列阅读入口时只使用工具已返回的完整链接，标签采用资料中已有章节或内容名称；没有时用论文简称。不要单独输出 `#page`、裸 API 地址或“同上链接”，不凭空拼接其他版本，不重复堆砌来源清单。
关键企业来源使用实际已读的 [E:证据ID]；精确摘录用 evidence_read 返回的 quote_id，不猜句柄。
普通研读与文件交付直接完成。只有用户要求保存正式业务报告或证据卡时，用 tool_search 发现对应工具；报告可按子问题用 matrix_record 保留事实和来源，再 report_check，通过后以相同 title/text 执行 report_save。报告修改后重新核查。
核查服务不可用时保留分析与草稿，明确正式报告尚未保存，不能谎称科学核查通过；也不把技术故障说成论文内容有误。
